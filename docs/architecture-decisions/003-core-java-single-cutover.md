# ADR-003：生产单 Core 一次性切换

日期：2026-08-24

状态：已接受

## 背景

用户明确不接受双 Core。Core 独占 PostgreSQL 正式写入，并包含计费、ReviewArtifact、SSE、Outbox 和
后台补偿；在生产按路由切流或双写会制造不可证明的一致性问题。

## 决策

- 生产始终只有一个名为 `core-api` 的服务和一个正式数据库写入者；
- 开发允许 Python/Java 对照，但必须使用两个隔离数据库；
- Java 在全量完成前不接管任何生产路由；
- 最终镜像沿用 `inkforge-core-api:<sha>`、服务名、网络别名、端口、上传卷和环境变量边界；
- 切换通过 `docker compose up --no-build -d --wait` 替换同名容器；
- 切换前按实际运行容器的不可变镜像 ID 冻结 Web、Core、Agent 精确回滚组合，不要求三者历史标签相同；
- 失败时恢复冻结组合中的上一 Python Core 及配套 Web、Agent，不从历史标签猜测版本；
- 稳定观察期结束后才删除 Python Core。

## 切换门禁

- 公共/内部契约、Web、Agent、CLI、数据库和媒体全量测试通过；
- `novelwriterdev` 验收通过，正式库只读指纹通过；
- 没有不可安全中断的活动任务，或已证明可恢复；
- 生产备份和恢复清单可用；
- 上一 Python 镜像存在并已完成回滚演练；
- Java 在 448 MB Core 限额和 2 核 2 GB 整机预算内稳定；
- 用户批准具体提交和切换窗口。

## 禁止方案

- Python 与 Java 双写同一表；
- Nginx 按路由、用户或百分比拆流；
- 新增 `core-api-java` 生产服务并长期并行；
- 为了迁移执行未批准 DDL；
- 把手机号、支付或视频生产启用混入切换；
- Java 失败后继续带病运行而不回滚。

## 后果

- 迁移周期更长，必须在测试环境完成全量覆盖；
- 生产切换窗口更集中，但回滚边界清晰；
- Java 和 Python 必须在同一数据结构与契约上保持可替换，直到观察期结束。
