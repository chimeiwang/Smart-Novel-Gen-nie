# 章节影视化浏览器验收收敛

状态：已完成
日期：2026-08-23

## 1. 背景

在本地 Chrome 真实登录实例中，已经完成“上传角色参考图 → 确认权利 → 批准视觉版本 →
逐镜绑定 → 重新生成即梦提示词 → 手动编辑 → 保存正式版本”的完整链路。Core 与开发库中的
不可变版本、镜头参考集合和 PromptVersion 冻结关系均正确，但页面和提示词质量门禁暴露出四类
产品问题：

1. 待审的 33 镜候选与当前正式的 27 镜方案同时存在时，顶部指标始终显示候选数据，而视觉设定、
   分集和提示词实际操作正式数据，用户无法确认自己正在修改哪一版；
2. 旧提示词候选正确保留生成时的空参考快照，但页面只显示“未绑定”，没有说明当前镜头已经新增
   参考，也没有直接提供“按当前参考重新生成”的动作；
3. 角色、地点和道具并行加载期间先显示“0 项”，真实空库还会把首项选择建立在不存在的元素上；
4. 模型在负面约束中加入“只保留暖黄机械火花”等正向画面要求。该效果没有正式镜头、来源、相关
   设定或视觉参考依据，也没有进入 `qualityWarnings`。

此外，影视化步骤已经增加到四步，但 CSS 仍按三列布局，导致步骤在窄工作区中换行，进一步削弱
流程上下文。

## 2. 目标

1. 页面上的方案状态、指标、镜头选择和后续编辑始终指向同一个明确版本。
2. 历史提示词继续展示自己冻结的参考图，同时能识别当前镜头参考已经变化，并提供显式重新生成入口。
3. 设定卡加载中、真实空库和加载失败是三个不同状态，不再用瞬时 `0 项` 混淆。
4. 对没有正式依据的高成本视觉效果和混入负面约束的正向画面要求进行有证据的质量纠正与告警。
5. 四个影视化步骤稳定使用四列，不新增响应式或 UI 框架。

## 3. 非目标

- 不自动把当前镜头参考覆盖到旧候选或旧正式提示词；
- 不自动批准参考图、保存提示词或确认待审镜头方案；
- 不通过开放词库禁止所有创意细节，也不自动删除模型生成的视觉元素；
- 不修改公共 API、共享服务契约或 PostgreSQL schema；
- 不调用即梦视频生成 API。

## 4. 产品与状态设计

### 4.1 候选方案与正式方案

影视化工作区按当前步骤选择唯一操作上下文：

| 当前步骤 | 操作方案 | 指标标签 |
| --- | --- | --- |
| 拆镜与审镜 | 待审候选优先，没有候选时使用正式方案 | `待审候选` 或 `正式 vN` |
| 在镜头间分集 | 当前正式方案 | `正式 vN` |
| 角色与场景稳定 | 当前正式方案 | `正式 vN` |
| 逐镜提示词 | 当前正式方案 | `正式 vN` |

若待审候选和正式方案同时存在，后三步继续允许用户处理未被候选覆盖的正式版本，但必须展示：

> 当前正在处理正式 vN（X 镜）；另有待审候选（Y 镜），确认后才会成为新的正式版本。

提示提供“返回审镜”按钮。镜头选择、指标和内容面板必须使用同一方案，不能再由候选 Key 驱动正式
镜头详情。

### 4.2 提示词参考快照

候选和正式 PromptVersion 的参考图属于历史快照，当前镜头参考集合属于可变 Head。页面必须：

- 候选存在时展示候选冻结参考；没有候选但有正式版本时展示正式版本冻结参考；两者都没有时才展示
  当前镜头参考；
- 按顺序比较 `canonVersionId + assetId + strength`，不只比较图片数量；
- 快照与当前集合不同时保留历史展示，并提示“当前镜头参考已更新”；
- 提供“按当前参考重新生成”按钮，由新的 Prompt 任务冻结当前集合；
- 当前集合为空、历史快照也为空时继续显示普通稳定性 warning；不能用当前 Head 冒充旧版本来源。

### 4.3 设定卡加载

视觉设定面板新增显式 `loading` 状态：

- 加载中：计数显示“加载中”，列表显示“正在加载角色、地点和道具…”；
- 加载完成且为空：显示“暂无可用设定卡，请先在创作资料中创建角色、地点或道具”；
- 加载失败：保留现有错误提示，不伪装成空库；
- 只有真实存在首项时才建立默认选择，当前选择已经不存在时才回退到首项。

### 4.4 提示词新增视觉元素检查

质量检查不从任意名词差异推断“幻觉”，只检查高置信信号：

1. `negativeConstraints` 出现“只保留、仅保留、允许出现”等正向画面要求时，提示该字段职责混用；
2. 候选在主体、动作、表情、摄影、声音，或负面约束中的正向子句加入高成本视觉效果，而该效果未
   出现在当前正式 Scene/Beat/Shot、来源范围、本镜相关设定投影或视觉参考 `includeFeatures` 中时，
   提示“新增了正式镜头未确认的视觉效果”；
3. 首次响应出现上述问题时进入现有一次纠正调用；纠正后仍存在时作为非阻断 `qualityWarnings` 返回，
   交给用户编辑；
4. 禁止因为该检查自动删除文字、补造来源或使第二次响应硬失败。

首版只覆盖高信号制作效果，例如火花、火焰、爆炸、闪电/电弧、粒子、光束/光柱、浓烟、雨雪和
血迹。普通色温、材质、自然环境和已存在的雾不因词语差异被机械判错。

## 5. 实现边界

### Web

- `ChapterAdaptationWorkspace` 按步骤选择候选或正式方案，并向指标区传递明确标签；
- `PromptEditor` 同时接收历史快照与当前镜头参考，渲染差异提示和重新生成动作；
- `visual-canon-state.ts` 提供有序参考集合比较纯函数；
- `VisualCanonPanel` 区分加载、空库和失败；
- `globals.css` 把影视化步骤改为四列，并为版本上下文与参考变更提示复用现有 notice/button 语义。

### Agent Service

- 在现有 `_collect_generated_prompt_issues` 中增加保守的正向约束和视觉效果来源检查；
- 继续使用现有“一次纠正，第二次非阻断 warning”流程；
- 不修改 Schema、编译顺序、模型调用预算或 Core 回调契约。

## 6. 验收标准

1. 存在 33 镜待审候选和 27 镜正式方案时，审镜页显示“待审候选 · 33 镜”，提示词页显示
   “正式 vN · 27 镜”，并说明另有候选待确认。
2. 从候选切到提示词时，不会因为候选独有的 `S28..S33` 导致正式镜头选择为空。
3. 旧空参考候选与当前一张参考图并存时，页面显示历史空快照语义、当前参考已更新说明和重新生成按钮。
4. 新候选冻结当前参考后，差异提示消失并显示精确图片、职责、版本和强度。
5. 设定卡请求完成前不显示 `0 项`；真实空库不会抛错。
6. “不出现霓虹，只保留冷蓝环境光与暖黄机械火花”触发正向约束职责混用和未确认火花效果检查；
   “不出现霓虹”本身不被当成新增霓虹。
7. 相关 Web 与 Agent 测试、TypeScript、ESLint、Pytest、Ruff 和 Mypy 通过。
8. Chrome 真实回归能完成视觉绑定、按当前参考重新生成和正式提示词保存；开发库可保留验收版本，
   生产库无变更。

## 7. 实施验证

- 存在 33 镜待审候选与 27 镜正式方案时，Chrome 中审镜页显示“待审候选 · 33 镜”，提示词与
  视觉设定页显示“正式 v1 · 27 镜”，并提供“返回审镜”；四步导航保持单行四列。
- 在 `novelwriterdev` 验收数据中把 S01 当前参考强度由 70 调整为 71 后，旧正式提示词继续展示
  冻结的强度 70，并出现“当前镜头参考已更新”和“按当前参考重新生成”；重新生成候选后冻结
  强度 71，人工检查并保存正式版本后差异提示消失。
- 新生成的 S01 提示词没有加入来源、正式镜头、设定或参考图未支持的火花、粒子等制作效果；
  S26 候选继续展示独立的表情与视线信息。自动化用例同时覆盖“暖黄机械火花”的一次纠正以及
  “不出现霓虹”不被误判为新增霓虹。
- Web 289 项、API Client 3 项、视频 Agent 相关 150 项测试通过；TypeScript、ESLint、Ruff、
  Agent Service Mypy 与 `git diff --check` 通过。
- 本轮未修改公共 API、共享 DTO 或数据库 schema；只写入 `novelwriterdev` 验收数据，生产库无变更。
