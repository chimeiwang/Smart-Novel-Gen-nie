# 章节正文提交协议临时修补

状态：已实现并通过本地回归；生产状态以发布流程和实际部署核验为准。
验证记录见 [本地验收](../audits/2026-09-28-chapter-artifact-protocol-hotfix.md)。

## 问题与目标

普通章节生成复用的 `BeginArtifactArgs` 包含正文和选区两套字段，JSON Schema 无法表达现有跨字段校验。
一次读取参数纠正还会耗尽整个 AgentRuntime 调用的纠正机会，之后正文提交即使可修正也会直接失败。
本次只改善失败反馈、有限恢复和诊断，不拆工具、不重构工作流。

## 设计与边界

- 为正文缺失、正文为空、选区字段不完整、正文与选区混用等校验提供稳定错误类型；保留原校验强度。
- 纠正提示只包含安全派生诊断和服务端固定指令，不回放无效响应、参数值或推理内容。
- `write_chapter` / `rewrite_scene` 的 primary、reviser 明确要求 `kind=chapter_draft`、summary 和完整非空 content；其他字段省略。返工身份仍由现有权威草案校验器继承。
- 默认仍是每次 AgentRuntime 执行一次协议纠正。仅当前述纠正用于纯读取工具响应且已经成功，之后 `begin_artifact_output` 的 Pydantic 参数失败才额外纠正一次。
- 每次执行最多两次纠正；任何纠正响应再次失败立即收敛，不恢复完整任务、不重置计数。其他操作、选区、Reviewer、质量检查和 V2 单 Step 不扩充预算。
- 整包预检、权限、输出完整性检查、独立模型授权及用量上报不变。失败包不执行任何工具、不保存候选。
- 在现有 Agent 服务日志记录 runId、稳定失败分类、脱敏 loc/type、已用纠正次数及下一步动作，覆盖首次失败与耗尽失败；不记录参数值。

本规格仅补充 [原有协议恢复规格](2026-08-29-deepseek-tool-protocol-recovery.md) 中普通章节的有界例外。
不修改公共接口、数据库、ReviewArtifact、生产配置或缺少终止事件时的图级回退。

## 验收

回归复现读取纠正后正文提交失败，并验证额外一次成功、再次失败停止、参数不泄漏、用量逐次授权，
以及其他模式仍保留原预算。运行相关 pytest、仓库 Ruff、共享协议及工作流 Mypy 和 `git diff --check`。
本地受控 Provider 验证不代表真实供应商或生产验证。
