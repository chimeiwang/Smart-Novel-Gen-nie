# Seedance 2.5 接入与设定定妆产品设计

日期：2026-09-09

状态：产品与接入设计草案；尚未修改业务代码、契约或数据库。

用户已明确：最终视频模型采用即梦／Seedance 2.5；希望复用项目现有设定，增加定妆等锁定能力。

本文细化并修订[连载短剧／漫剧生产级产品规划](2026-09-09-serial-drama-production-product-plan.md)的供应商、生成粒度、声音与设定设计。接入渠道沿用当前项目的**火山方舟国内官方 API**；BytePlus、即梦网页产品和第三方中转的接口／价格不混入国内契约。

版本拆分：用户要求第一个版本约为 8 小时实现和验证工作量。V0.1 收敛为“设定单图定妆与镜头参考闭环”，复用现有结构，不包含新模型接入、真实付费试制或生产开放。本文的多图、声音、片段与编辑等完整目标分配至后续版本，详见[视频功能版本计划](../plans/2026-09-09-video-product-release-plan.md)。本文其他章节的首发目标指后续完整产品首发，不表示全部纳入 V0.1。

## 1. 结论

1. 以 Seedance 2.5 的多模态参考、原生音视频、编辑和延长能力组织制作，保留作者审核、成本和恢复边界。
2. 设定卡新增“视觉定妆／声音”视图，复用现有角色、地点、道具及视觉版本；不要求作者另建一套同名角色库。
3. 定妆锁定的对象是**经作者确认的参考版本与引用关系**。系统保证输入依据不被悄悄替换；生成结果是否保持人物一致，需要实际审片。
4. 生成单位支持单镜和连续叙事片段。逻辑镜头、供应商生成片段、实际剪辑区间各自保存，不能只把现有单镜时长上限改成 30 秒。
5. 优先验证原生音视频与声音参考，独立 TTS 改为经验证需要的后期补救，不再预先规定为所有首发场景的必选供应商。

## 2. 官方文档依据与产品约束

2026-09-09 已读取火山方舟公开网页中提供的完整正文。网页检索器无法展开时，使用公开 HTML 内的 `MDContent` 读取，不涉及登录或付费调用。当前代码基线仍为 `0a7e701`；模型账号开通、配额和真实生成尚未验证。

### 2.1 能力如何变成产品功能

| 官方能力 | InkForge 产品设计 | 必须遵守的约束 |
| --- | --- | --- |
| 普通生成时长 4～30 秒，可自动选择 | 由作者确认单镜／片段及预算 | 30 秒是上限；小于 4 秒的剪辑镜头可取自较长素材，生成量和采用量分别展示 |
| 多模态参考最多 30 图、10 视频、10 音频 | 从设定定妆、场景、角色声音及动作参考组装输入 | 视频总时长、音频总时长各不超过 30 秒；按片段需要选择 |
| 首帧、首尾帧生成 | 从已确认分镜画面控制开始／结束构图 | 与全模态参考模式互斥；此模式使用 adaptive 画幅 |
| 原生音视频 | 用确认对白、声音参考和场景声音要求生成候选 | 实际对白、说话人和音色逐项复核；不能将计划字幕视为声音正确的证明 |
| 视频编辑 | 作者按问题、时间区间提出修改，形成新的候选 | 保留原片；完整对照结果，不能保证请求范围外像素完全不变 |
| 视频延长 | 对已采用片段显式向前／向后续作 | 新任务、新报价、新版本；核对返回片段的实际组成与拼接边界 |

普通生成范围、模态及角色约束来自[国内创建任务 API](https://docs.volcengine.com/docs/82379/1520757)；叙事、参考和时间戳编辑能力另见[字节 Seedance 2.5 官方介绍](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)。质量描述为供应商能力说明，不是 InkForge 已完成的验收。

### 2.2 请求模式应由界面操作明确选择

| 作者操作 | 供应商请求设计 |
| --- | --- |
| 按定妆生成新片段 | 图／视频／音频各用对应 reference 角色，明确 `omni_reference_task_type=reference` |
| 按首帧生成 | 一张 `first_frame` 图片，`ratio=adaptive` |
| 按首尾帧生成 | `first_frame` 与 `last_frame` 图片，`ratio=adaptive` |
| 修改已有片段 | `omni_reference_task_type=edit`，提供参考视频，`ratio=adaptive`、`duration=-1`；待编辑视频须为 4～30 秒 |
| 延长已有片段 | `omni_reference_task_type=extend`，提供参考视频，`ratio=adaptive`，冻结延长方向和意图 |

首尾帧模式不再额外混入定妆图片或声音参考。需要两者配合时，先依据定妆准备并确认首尾帧；或改用全模态参考，通过文字描述首末状态，但不能把后者标成强约束首尾帧。

采用显式模式以减少意图与参数不一致；不能把所有操作都作为 `auto` 提交。即使创建成功，后续仍可能因模型判断的任务类型不同而失败，页面必须保留异步失败和费用处理路径。[创建接口任务类型说明](https://docs.volcengine.com/docs/82379/1520757)

### 2.3 媒体与费用影响

- 定妆素材进入供应商前重新校验数量、字节大小、尺寸、时长和编码；本地允许上传不代表可以直接发送。
- 生成原片、浏览器预览代理和最终交付分别保存。1080p 的 10bit HEVC 以及专业 MOV 不能仅靠文件扩展名判断浏览器可播放；预览转码要保留原片供历史追溯和后续编辑。
- 原生有声输出为单声道混合音轨，不能承诺返回独立对白、音乐与环境声。后配音前须明确是否会覆盖原环境音，避免双对白。
- 自动时长与编辑任务须按可计算的最高费用预留；成功后按供应商实际计量结算，不按“作者只修改了 3 秒”推断仅收 3 秒费用。
- 低成本预演由静帧时间线、较短试制或经报价的低清生成实现；不能把其他 Seedance 版本的 `draft` 或离线折扣能力直接移植到 2.5。

模式与媒体限制按[创建接口模型适用范围](https://docs.volcengine.com/docs/82379/1520757)校验；素材用途、故事板与参考表达按[国内 2.5 提示词指南](https://docs.volcengine.com/docs/82379/2607689)设计。多宫格故事板主要提供剧情参考，不视为每一格像素或切点的保证。

### 2.4 国内计费与取消快照

核对日的国内在线推理刊例价如下，单位为元／百万 token：

| 输出档位 | 输入不含视频 | 输入包含视频 |
| --- | ---: | ---: |
| 480p／720p | 70 | 42 |
| 1080p | 77 | 46 |

1080p 当前有北京时间 2026-08-14 14:00 至 2026-09-17 14:00 的 72 折活动；报价保存有效期，不将活动价写成长期价格。供应商只对成功生成计费，精确计量依据 `usage.completion_tokens`；含视频输入存在最低用量规则，因此单位 token 较便宜不等于该任务总价更低。最低用量明细表本轮未读取，报价上线前必须补齐。[国内模型价格](https://docs.volcengine.com/docs/82379/1544106)

作者取消规则：本地未提交时停止派发；供应商排队时申请取消并回读；运行中不能承诺可取消。成功／失败／过期任务的供应商 DELETE 是删除记录，不作为取消或退款操作。[取消／删除任务](https://docs.volcengine.com/docs/82379/1521720)

## 3. 现有设定已经具备什么

当前角色已有外貌 `appearance`、性格、身份、背景、说话习惯 `speechStyle` 等；地点、道具也已有描述字段。它们是小说事实，应继续作为统一身份入口。

开发视频域已经具备：

- `VideoVisualCanon`：按 `projectId + settingKind + settingId + duty + variantKey` 唯一定位视觉槽。
- 职责 `identity / costume / scene / prop`：分别对应角色身份、服装、场景和道具。
- 候选图与正式图分开；包含特征、排除特征、默认参考强度和当前版本已存在。
- `VideoVisualCanonVersion`：作者批准后创建不可变版本，保存一张素材、当时设定名称、视觉标签、保留／排除特征、批准人和哈希；它没有冻结整份小说文字设定。
- 镜头绑定具体视觉版本，提示词与生成任务继续冻结精确引用，换图不会回写旧输入。

因此，**新增设定界面字段与新增数据库列是两件事**。第一步可以复用已有模型和公共 API，把能力带回设定入口；不需要再给 `Character` 加一个与视觉 Head 竞争的 `currentImageUrl` 或 `isLocked`。

## 4. 设定卡中的产品字段

### 4.1 作者看到的结构

角色卡提供“文字设定、视觉定妆、声音、使用记录”；地点和道具显示适用的文字／视觉／记录页签。只有一个视频项目时默认选中；存在多个项目时明确显示写实版、动画版等上下文。

| 作者字段／操作 | 保存位置或已有能力 | 本轮判断 |
| --- | --- | --- |
| 人物外貌、性格、说话习惯 | 现有小说角色字段 | 直接复用 |
| 当前定妆、确认状态、版本号 | 当前视觉槽及已批准版本 | 聚合展示，不新增重复锁定字段 |
| 必须保留特征、禁止变化 | 已有 includeFeatures / excludeFeatures | 复用；描述具体特征，不填写“绝对一致”空泛要求 |
| 服装／场景／道具变体 | 已有 duty + variantKey | 复用；界面用“日常服装”“受伤后”“雨夜”等自然名称 |
| 主定妆图与多角度参考组 | 当前版本只有一个 assetId | 新增有序素材组设计，按一版整体确认 |
| 音色与声音参考 | 当前 speechStyle 仅是文字风格 | 新增声音参考版本，不能把音频塞入说话习惯文本 |
| 当前渠道可用状态与素材来源 | 本地使用权确认不能代替供应商接收规则 | 新增供应商素材凭据映射与使用前复验 |
| 项目画风、时代、色彩、材质规范 | 当前项目没有完整风格版本 | 新增项目级风格版本，角色引用其版本 |
| 定妆依据的文字设定版本 | 当前视觉版本未保存角色外貌等完整来源投影 | 新增相关文字来源快照／哈希，用于展示后续文字变化 |
| 哪些集／镜头正在使用、换版影响 | 现有绑定关系可支撑部分查询 | 先补影响查询与入口，跨集／新片段继续扩展 |

同一个小说角色可以在两个视频项目中有不同定妆。小说 `appearance` 不因某个视频项目改为动画风格而变化；视频中的换装、临时伤势与表演姿态也不覆盖角色长期设定。

### 4.2 多图定妆组

一个已确认定妆版本应能带有主图及必要的侧面、全身、局部辨识特征等参考，并为每张图记录用途、顺序、素材 ID 和内容哈希。视角不是角色身份变体，不能把“正面”“侧面”各建成互相竞争的当前身份。

建议在现有视觉版本旁新增有序成员结构；旧单图版本映射为一张主图，保持可读。新增成员必须随新版本整体创建，禁止向已经批准的版本继续追加图片。确切表名、约束与迁移在实施规格中确定。

衣服与脸仍按不同职责选择，角色不同年龄／身份变体由作者显式区分。系统可推荐组合，不能把所有服装版本一起发给模型让它自行决定。

### 4.3 声音参考版本

声音版本绑定现有角色和视频项目，记录参考音频、允许用途与来源、声音描述、读音要求、批准信息和文件哈希。需要区分“参考音色”“参考节奏”“必须说出的对白”，避免模型误将试音文本当作本集台词。

首发优先实测原生音视频和声音参考能否通过三集一致性验收。不能稳定复现角色声音时，提供重新编辑该段音频／视频或明确静音后配音的路径；独立 TTS 是否必需，由目标制作形态的结果决定。

一条原生混音里只替换一句话可能影响环境声和口型。系统必须显示影响，不能承诺只新增一个音轨即可无损修复。字幕对齐实际采用的声音，而不是直接复制计划对白就完成校验。

### 4.4 “锁定”的具体规则

1. 上传或生成新素材只产生候选；当前定妆继续有效。
2. 作者点击“确认为定妆”后，创建不可变版本，成为此视觉槽的默认定妆。已绑定镜头继续使用原版，升级须由作者确认。
3. 修改时使用“制作新版”，比较后由作者采用；旧版本与已生成内容继续可读。
4. 更新默认定妆，只影响未来明确选择新版本的任务；已有镜头显示“可升级”，不自动替换。
5. 一次生成冻结全部图片、声音、画风、变体、顺序、台词和目标动作。任务开始后设定变化不影响该任务。
6. 输入锁定不能保证生成像素或音色完全一致；实际结果仍需对照定妆审片。

当前的 `strength=1..100` 不是官方人脸锁定百分比，当前 `submit_render` 也没有把该数值作为 API 参数传出。默认作者界面不展示虚假的“一致性百分比”；若后续保留为内部选择优先级或提示词建议，必须明确其真实作用。

### 4.5 供应商素材可用性与长期定妆

国内接口对含真人人脸的普通参考上传有专门限制，提供授权真人、预置虚拟人像及部分模型原始产物等路径；不能把“作者已勾选使用权”视为所有输入都能发送。接口支持供应商 `asset://` 引用；同账号近 30 天的指定 Seedance 含人脸原始视频具有文档所述的再输入路径，更细授权流程仍须核验。[国内人物与素材输入规则](https://docs.volcengine.com/docs/82379/1520757)

产品分别显示“定妆已确认”和“当前生成渠道可使用”。长期定妆版本保存本地素材及权利事实；供应商凭据另外记录渠道、账号作用域、素材 ID、原生成任务／模型／时间与复验状态，不把供应商 asset ID 当作小说角色 ID。

原片与预览转码分开保存；不推断转码后、跨账号或超出供应商认可时间范围的文件仍享有原始产物资格。再次生成、编辑或延长前复验可用性，失效时说明补充素材或重新授权路径；旧成片和历史定妆仍保持可查看。凭据更新不修改已冻结输入，建立新的映射记录。

## 5. 从设定到一次 Seedance 请求

以“林然穿雨衣，在车站与顾青对话”为例，系统建议：林然身份当前版、雨衣变体、顾青身份与服装、车站夜景、两位角色声音参考；作者查看缩略图和试音后确认。

Core 冻结实体与素材版本，再按本次实际发送顺序生成图片／视频／音频别名。提示词明确每个素材负责谁、服装还是背景，以及两位说话人的对白。镜头特有的站位、表情、动作与运镜来自分镜，不放回长期定妆。

别名是本次请求的投影，不是永久角色 ID。素材顺序改变必须重新编译和确认，不能只换 URL 而保留旧的“图片1”。参考超出供应商能力时，提示作者精简或拆片段，不能静默丢掉角色或声音素材。

定妆图的目标来源包括上传、经作者批准的已有 Take 抽帧，或后续独立图片生成能力。当前抽帧产物职责是 keyframe，要作为身份／服装等定妆候选，还需补充职责转换与候选入口，不能直接将其当成现有完整能力。Seedance 的视频生成能力不能直接表述为独立角色图片生成 API；从视频抽帧也要记录成本、来源和允许复用条件。

## 6. 生成片段、镜头与编辑

### 6.1 三个粒度

- 逻辑镜头保存导演意图、来源、角色与预计时间。
- 生成片段保存一次供应商请求，可关联同集内连续的一个或多个镜头。
- 实际媒体区间保存真实起止位置和对应镜头，是粗剪与字幕对齐依据。

首发只组合同集、连续镜头。多镜片段先用于同场景、角色与声音连续的片段；重要转折或需要单独返工的镜头可独立生成。用户看到两种方案的生成量、成本和返工范围后选择。

若模型没有按计划切镜，或漏掉其中一个动作，系统不能按计划时间自动裁切并把所有镜头标成完成。可以人工校正实际区间、整段采用，或退回重新分组。原有单镜 Take 保留旧语义；新片段结果不能冒充某一个旧 shotId 下的完整多镜资产。

### 6.2 有界编辑与延长

作者选择片段、修改目的和时间范围，系统冻结源视频和修改要求、重新报价。供应商返回新候选后，对照整段画面与声音，确认实际时长、切点和意外变化。

局部编辑与延长列为 2.5 的目标能力，不再笼统推到遥远后续；发布顺序仍以实测为准。优先开放“修改片段中的角色／动作／声音”与“向后延长”；白模、绿幕、复杂区域修复后置。

若产品提供“只替换中间区间”，应由剪辑层明确引用新片段区间，前后继续用原采用素材，并复核动作与声音边界。不能仅凭供应商成功就声称未选区内容完全没变。

编辑后的实际时长可能与源片略有差异，不能强行套用旧字幕和切点，也不能静默截断或补齐。延长结果是续段还是包含原段，按返回媒体事实验证，不按按钮名称猜测。

## 7. 当前实现需要怎样演进

| 当前实现 | 需要的改变 |
| --- | --- |
| 设定卡只有文字编辑；视觉编辑器依赖当前章节和选中镜头 | 抽出独立设定视觉编辑器，拆镜前即可定妆；镜头绑定另保留 |
| 每个视觉版本一张图片 | 增加版本化多图成员；旧单图版兼容 |
| 没有角色声音／项目画风版本 | 新增明确领域契约与版本引用，不塞入现有描述字段 |
| 逐镜契约限定 2～12 秒、20 张图 | 按 2.5 和具体模式更新预检；小于最短生成时长时明确展示生成／采用差异 |
| 所有图片发为 reference_image；无视频／音频参考 | 增加按模式判别的图片、视频、音频引用和互斥校验 |
| 一次任务只属于一个镜头 | 新增生成片段与实际媒体区间，保留历史单镜路径 |
| 生成与重试为主要入口 | 增加明确的 reference／edit／extend 命令和报价，不靠提示词隐式切模式 |
| 只存当前清单和供应商结果，缺渲染账务 | 延续总规划中的报价、预留、结算、未知提交与归档恢复 |
| 设定删除检查未包含视频引用 | 增加使用中保护与影响清单，保留历史入口；归档另设计 |

有视频引用的设定先阻止物理删除；以后支持归档时，禁止新绑定但保留历史访问。改编合并角色需要显式来源映射，不能按同名自动合并。当前并没有完整的设定合并产品操作，本次不伪造已有能力。

## 8. 验收与实施顺序

1. **设定入口整合**：在已有角色／地点／道具卡上管理现有单图定妆和变体，验证批准、版本切换、历史引用与删除保护。
2. **2.5 接口校准**：分别验证多模态、首帧、首尾帧；错误组合调用前明确拒绝；任务类型异步错误能解释和收尾。
3. **多图与声音**：扩展参考组及声音版本；同一角色跨三集核对外观、对白完整性和音色；确认是否需要 TTS 补救。
4. **多镜片段与剪辑映射**：测试计划三镜但切点偏移、漏镜、连续运镜等情况；不误报完成，能调整和退回。
5. **编辑与延长**：修改中段服装或一句对白，复核范围外变化、时长和字幕；延长后保存完整派生链与费用。
6. **生产发布**：按总规划补齐账务、归档恢复、原片与代理存储、媒体容量及经授权发布；不因模型公开就直接开启生产。

所有新字段和能力先设计公共契约，再生成客户端、实现 Java 和 Agent。多图、声音、画风、片段等持久化结构需要具名迁移设计；本轮规划不执行 DDL、不修改生产开关。
