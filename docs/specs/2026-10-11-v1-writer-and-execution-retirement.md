# V1 作家编辑原则与耐久执行引擎退役

日期：2026-10-11

状态：实现已提交并部署；提示词效果尚未通过真实文本验证，用户反馈朱雀特征反而升高，待对照正文定位。发布与验证边界见[审计](../audits/2026-10-11-v1-writer-engine-retirement.md)。

## 用户目标与授权

用户先要求将人工修稿中使用的编辑经验尝试加入现有作家 Agent 提示词，不新增 Agent 或独立编辑循环；随后要求删除 V2 并在完成后提交部署。明确范围后，用户选择“完整移除 V2 引擎，同时迁移仍依赖它的功能”。

本次以 V1 LangGraph、普通队列、Core 工具网关和 ReviewArtifact 为继续运行的主链。退役对象为 Core 调度、Agent 单 Step 执行、execution Redis journal 及相关新建路由组成的耐久执行 V2 引擎，不按名称中的版本号批量删除视频领域契约、日志格式或第三方 API。

保留小说、正文、大纲、设定、版本、候选来源、账号和账务数据。不执行 PostgreSQL DDL rollback、删表、清库、删除持久卷或重写历史引擎身份。旧记录继续可查询；仍在使用的业务功能迁移后才能删除执行依赖。本规格取代 2026-09-13 兼容回退中“继续保留完整 V2 执行引擎”的实施选择，保全数据、版本和账务的要求继续有效。

## 作家提示词

在现有 V1 作家静态提示中补充：对白符合人物知识与动机；避免重复解释；场景提供新的变化；动作服务具体场面；解决办法有依据和铺垫；保护有效内容和作品文风。提交前自检落实到正文，不输出过程、不建立禁词或检测分数门禁，不额外增加模型调用。初稿和作家承担的返工均使用该提示。

继续保持当前五个 Agent、已有章节计划约束、模型工具权限、全文候选、双复审和作者确认。不得把提示词优化声称为外部 AI 检测通过保证。

## 执行迁移与退役

1. 新长篇、中短篇、文风画像、质量检查和资料索引统一走已有 V1 业务入口。保留原请求幂等、同小说互斥、恢复、取消、用量与资料版本校验。
2. 独立 Episode 剧本和分镜当前依赖耐久执行，迁移为普通队列业务任务；继续冻结完整来源、验证受限修订范围、形成候选并由用户采用，不改正式视频方案规则。生产视频保持关闭，不调用真实 Seedance。
3. 旧运行、候选与账务仅保留必要的历史读取、来源验证和业务决定兼容。任何仍需执行的旧任务应在发布前排空、核对或以显式恢复方案承接，不能遗弃未送达回调、未知用量和未决预留。
4. 删除不再有调用者的 V2 执行器、调度器、注册表、新建路由、界面、专属测试及部署依赖。可复用的业务计算、版本协议、来源校验须先迁到业务或中立模块，不能通过重命名整个旧引擎伪装退役。
5. 公共接口先改 OpenAPI 并重新生成客户端；共享 Python/Java 协议一起核对。删除引擎不解释为删除历史数据库结构或不可变来源数据。
6. 当前需求与架构说明改为 V1 实现；历史审计和必要数据保全记录作为历史保留，不能改写历史发布事实。
