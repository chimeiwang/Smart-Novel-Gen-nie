# 设定库列表视觉重构规格

## 状态

- 日期：2026-08-06
- 状态：设计已确认，待实现
- 适用范围：长篇创作资料中的设定库
- 确认方案：方案 A，摘要列表
- 性质：纯前端信息架构与视觉重构，不修改接口、业务数据或 PostgreSQL schema

## 背景

当前设定库把列表项同时应用为 `list-item` 和 `list-item-button`。后者覆盖了前者的内边距、边框和背景，
导致每条设定退化成一条贴边的灰色文本带。人物名称、状态、所属、身份和长篇人物描述继续挤在两行通用
元信息容器中，缺少稳定的主次层级；长文本自然换行后相互黏连，用户很难快速定位人物，也无法预判点击
列表项会进入编辑。

该问题属于前端 DOM 结构和 CSS 职责冲突，与迁移数据内容无关。人物字段较完整时问题最明显，但地点、
势力、物品和术语继续沿用同一通用结构也会产生相同的可读性问题。

## 目标

1. 让用户在不打开编辑层的情况下快速识别设定名称、类型、状态和关键摘要。
2. 建立稳定的信息层级，避免长文本把列表压成连续灰条。
3. 保持 PC 工作台的信息密度，一屏能够浏览多个设定，不把页面改造成大面积展示卡片。
4. 让角色、地点、势力、物品和术语共享同一套列表骨架，同时允许各类型展示不同的关键字段。
5. 保留现有新增、点击编辑、删除、表单校验和数据请求行为。

## 已确认设计

### 整体布局

- 保留现有“左侧分类导航 + 中央设定列表”的工作台布局，不调整创作资料最外层三栏结构。
- 设定列表使用单列摘要行；每行是完整可点击区域，具有清晰边框、内边距、圆角和悬停反馈。
- 列表头显示当前分类名称、条目数量和新增按钮；新增按钮文案随分类变化，例如“新增角色”。
- 不在列表内展开完整详情。点击设定后继续进入现有编辑覆盖层，避免同时维护第二套详情视图。

### 摘要行结构

每个摘要行固定分为四个视觉区域：

1. **类型标识**：使用名称首字或轻量类型符号形成固定尺寸标识，不依赖新增图片资源。
2. **名称区**：第一行是设定名称，第二行是身份、类型或其他稳定的短字段。
3. **摘要区**：上方是状态、所属、境界等短标签，下方是最有辨识度的正文摘要。
4. **操作暗示**：行尾使用轻量箭头提示可进入编辑，不增加常驻按钮组。

人物摘要行在桌面端约为 `72px` 至 `88px` 高。正文摘要最多显示两行，超出部分使用 CSS 多行截断；
截断只影响列表展示，不得修改或截断接口数据、表单值和持久化内容。

### 各分类字段映射

| 分类 | 名称区次要字段 | 标签 | 摘要正文 |
| --- | --- | --- | --- |
| 角色 | 身份 | 状态、所属势力、境界 | 性格；缺失时回退到状态说明 |
| 地点 | 地点类型 | 父地点、气候 | 地点描述 |
| 势力 | 势力类型 | 总部地点 | 势力描述 |
| 物品 | 物品类型 | 稀有度、持有者 | 物品效果；缺失时回退到物品描述 |
| 术语 | 术语分类 | 无 | 术语定义 |

缺失字段不显示空标签，也不使用推测值补齐。若名称之外没有任何摘要字段，仍保留正常行高与编辑暗示。

### 视觉规则

- 继续使用 `DESIGN.md` 定义的暖纸色背景、安静表面、发丝边框和现有 CSS 自定义属性。
- 名称是唯一的强强调文本；身份和正文使用较弱文本色，标签只承担分类和状态，不与名称争夺视觉焦点。
- 活跃状态可以使用现有成功色的低饱和背景；普通标签统一使用中性弱背景。
- 当前列表项和悬停列表项通过边框、弱背景或内侧强调线表达，不使用大面积高饱和填充。
- 不引入 Tailwind、图标库、头像上传或新的全局设计系统。

### 响应式与可访问性

- 桌面端使用网格对齐类型标识、名称区、摘要区和行尾提示。
- 中等宽度下允许摘要区收窄，但名称区保持可识别；过长短字段使用单行省略。
- 小屏下摘要区换到名称区下方，仍保持整行点击，不产生横向滚动。
- 列表项继续使用原生 `button`，保留键盘聚焦、回车/空格激活和可见焦点状态。
- 装饰性首字标识和箭头不参与无障碍名称；按钮名称应包含设定类型和名称。
- `prefers-reduced-motion` 下不使用位移动画。

## 实现边界

预计仅修改以下前端范围：

- `apps/web/src/features/lore/lore-panel.tsx`：把通用元信息堆叠改为语义化摘要行结构，并集中生成各分类展示模型。
- `apps/web/src/app/globals.css`：新增设定库专用类，消除 `list-item-button` 对列表容器样式的覆盖冲突。
- 相关前端测试：验证各分类字段映射、缺失字段回退、可访问名称和列表结构。

不修改 Core API、生成客户端、数据库结构、现有设定字段、保存流程、编辑表单和删除逻辑。

## 实现约束

- 不能通过复制现有全局 `.list-item` 规则后继续叠加覆盖来修复；设定库摘要行应使用职责明确的专用类。
- 各分类的展示映射应集中处理，避免在 JSX 中为五种类型堆叠大量重复条件分支。
- 列表展示截断只能由 CSS 完成，不能在 TypeScript 中裁剪业务文本。
- 不为本次视觉修复引入虚拟列表、搜索、排序、批量操作或详情抽屉。

## 验收标准

1. 具有完整人物资料的角色列表不再显示为连续灰色文本带，每条记录边界清晰。
2. 用户无需打开编辑层即可识别角色名称、身份、状态、所属、境界和两行人物摘要。
3. 人物摘要超过两行时只在列表中视觉截断，打开编辑后字段内容完整且未被修改。
4. 地点、势力、物品和术语使用相同摘要骨架，并按字段映射展示各自信息。
5. 列表项支持鼠标和键盘操作，焦点状态清晰，点击行为与改版前一致。
6. 新增、编辑、删除、分类切换和空状态行为保持正常。
7. 在当前创作资料三栏桌面布局中不出现横向滚动；窄屏下摘要区可以换行重排。
8. 相关前端测试、`npm run typecheck` 和 `npm run lint` 通过。

## 非目标

- 不重做创作资料整体导航、右侧审核栏或章节编辑器。
- 不新增详情抽屉、角色头像、关系图谱、筛选、搜索、排序或批量编辑。
- 不调整设定数据模型、迁移数据或生产数据库内容。
- 不把所有设定全文直接展示在列表中。
