# 模型授权生命周期调整规格

## 目标

将 Core API 为单次真实模型调用签发的模型授权生命周期调整为 1200 秒，确保耗时超过两分钟的中短篇生成在模型返回后仍能正常上报用量并完成任务。

## 非目标

- 不修改 Core API 与 Agent Service 之间的 Ed25519 服务令牌生命周期；服务令牌仍遵守现有最多 300 秒的约束。
- 不修改模型输出额度、积分价格、用量幂等规则、数据库结构、Agent 编排或 ReviewArtifact 状态机。
- 不自动重试已经失败的写作任务。

## 当前事实

- Core API 当前签发 120 秒的模型授权，而模型调用可能持续数分钟。
- Agent Service 在模型调用完成后才携带原授权上报实际用量；授权过期会使上报返回 `MODEL_GRANT_INVALID`，并导致整个写作任务失败。
- 模型授权独立于内部服务请求令牌，并绑定用户、小说、任务、运行、Agent、提供方、模型、请求标识、输出上限和计费属性。

## 设计

- 在 Core API 计费模块中维护唯一的模型授权生命周期常量，值为 1200 秒。
- 授权签发使用该常量计算 `exp` 和 `expiresAt`。
- `ModelGrantClaims` 接受不超过 1200 秒的授权，拒绝零寿命、负寿命或超过 1200 秒的载荷；已有较短授权保持可验证。
- 验签器继续保留现有 30 秒时钟偏差容忍；对外返回的 `expiresAt` 和令牌声明生命周期仍精确为 1200 秒。
- 用量上报继续校验完整授权绑定和输出上限，数据库中的 `requestId` 幂等结算规则保持不变。

## 影响范围

- Core API 模型授权声明校验与授权签发服务。
- Core API 模型授权单元测试。
- AI 写作需求中对模型计费授权生命周期的当前事实说明。

## 验收标准

- 新签发授权的 `exp - iat` 精确等于 1200 秒，响应中的 `expiresAt` 与之相同。
- 1200 秒生命周期的授权可签发并验证，1201 秒生命周期的授权被拒绝。
- 授权在超过旧的 300 秒上限后仍可验证，超过 1200 秒及既有时钟偏差窗口后被拒绝。
- 已有篡改校验、完整资源绑定、输出额度和用量幂等行为不变。
- 相关 pytest、Ruff 和 Mypy 验证通过，且不修改 PostgreSQL schema。
