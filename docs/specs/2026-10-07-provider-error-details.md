# 模型供应商完整错误诊断

状态：代码与本地验证完成，待本轮提交发布及生产复现。

## 背景与授权

2026-10-07 生产章节写作两次收到 DeepSeek HTTP 400。现有错误边界仅保存状态码、分类与请求 ID，
丢弃供应商返回的错误说明，无法确认被拒绝的字段。用户明确要求修改文件，让服务保存全部错误信息。
本规格取代 2026-08-24 失败可观测性规格中禁止保留供应商错误响应及异常文本的约束，仅限失败诊断；
凭据保护、正式内容审核、模型计费、重试和任务终态规则保持不变。

## 目标与范围

- DeepSeek 原始适配器与通用 OpenAI-compatible 适配器保留完整 HTTP 错误响应正文、状态、响应头、
  请求方法和经过脱敏的目标地址；JSON、纯文本和 HTML 错误均保留，不按长度截断。
- 连接、超时和响应协议错误保留可取得的异常类型、完整错误消息、因果链和调用栈；不采集局部变量。
- API Key、Authorization、Cookie、grantToken、密码及 URL 中的认证信息在构建诊断时脱敏；
  不另行复制正常请求正文、请求头、工具参数、模型推理或成功模型输出。
- 详细诊断放入独立异常属性，异常的 str/repr 和公共错误码继续保持简短，不把详情发送到 Core、SSE、
  任务状态或作者聊天回复。
- V1 ModelRuntime 将详情完整写入 Agent 服务日志及原任务人工日志的 model_failure 帧正文；
  大正文不进入有 64 KiB 上限的结构头，日志正文中的换行或帧标记不能伪造日志结构。
- V2 单 Step 的 Provider 错误详情进入带 run/step 身份的服务日志，不改变 journal、回调和计费契约。
- 旧错误对象没有详细信息时保持兼容；日志记录失败不能覆盖原始供应商错误。

## 非目标

不恢复已经丢弃的历史响应，不增加应用自动重试，不修改 strict、模型名称或输出额度，不修改数据库结构。
视频和 embedding 专用适配器的错误采集不在本次范围内。本地测试使用替身响应。

用户随后明确授权完成后提交部署，再重试最后一次失败任务定位根因，修复后再次提交部署。生产操作沿用
现有发布门禁，任务重试走生产 Operator 公共入口，只覆盖原失败章节及操作，不自动确认生成的草案。

## 验收

- HTTP 400 JSON 错误中的 message/type/code/param 及其他字段完整可查；非 JSON 响应也完整可查。
- 超过 64 KiB 的错误正文可完整追加并回读；正常错误描述与 traceback 不截断。
- 响应正文、响应头、异常链与地址中回显的凭据均脱敏，异常 str/repr 和公共终态不泄漏详情。
- 日志写入异常仍传播原始 MODEL_PROVIDER_FAILED；计费及既有重试决定保持一致。
- 运行相关 Provider、Runtime、人工日志和 Executor 测试、仓库 Ruff 与共享工作流 Mypy。
