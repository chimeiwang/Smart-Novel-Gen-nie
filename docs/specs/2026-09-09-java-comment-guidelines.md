# Java 必要注释补齐与持续维护

日期：2026-09-09

## 目标

检查整个 Java 工程并补充必要且简洁的中文注释，让维护者理解业务约束、调用契约和不直观的实现原因。
注释密度不作为质量指标；代码命名已经表达清楚的内容无需重复。

## 设计与范围

- 在根目录 `AGENTS.md` 固定后续 Java 开发的注释规则。
- 类和公开应用接口的职责或调用约束不直观时，用简短 Javadoc 说明。
- 方法用途无法从名称和上下文直接判断时，用一句方法级 Javadoc 说明整体职责；复杂方法按实际需要说明关键阶段或调用约束，默认保持简短，不逐字段解释。
- 对事务、并发、幂等、状态流转、异常恢复及兼容处理，解释必要的约束或原因。
- 不逐行解释语法，不为简单访问器、普通赋值或字段逐项补模板注释，不臆测历史设计意图。
- 修改实现时同步维护相关注释；明显重复或已失真的注释应删除或修正。
- 检查 `apps/core-api-java`、`packages/service-auth-java`、`packages/service-contracts-java` 和
  `tools/inkforge-cli-java` 的主代码；测试方法已有清晰中文行为名时不机械增加说明。
- 优先补齐 Spring 装配边界、公共应用端口、服务鉴权协议、CLI 命令组，以及业务服务中无法由命名直接表达的
  状态、并发、兼容和失败恢复规则。
- 对已经有足够职责说明和关键分支注释的耐久工作流、写作、审核及视频代码，不重复添加同义注释。

## 非目标与影响

本轮只修改规范、文档索引和 Java 注释，不修改接口、执行逻辑、数据库或部署配置。
后续随相关代码的新增和修改持续执行该规范。

## 验收

- 逐项核对注释与当前实现、现有测试及契约一致；不把推测写成事实。
- 对所有纳入本轮的 Java 文件核对差异，确保只新增或修正注释并保留工作区已有逻辑改动。
- 运行受影响模块的 Java 测试，确认行为保持一致。
- 检查本轮差异的空白与格式；本轮不新增仅验证注释的测试。

## 验证结果

- 已扫描四个 Java 主代码目录共 763 个文件，测试源码不在本轮修改范围；已有测试工作区改动保持原样。
- 已补充 Spring 装配、身份与服务鉴权、计费、章节状态、审核采用、V1/V2 写作、耐久工作流、视频制作、
  媒体子进程和 Java CLI 中缺少的类职责、非直观方法用途及关键分支原因。
- 复查后，20 行以上主代码文件均至少有职责或关键约束说明；简单 DTO、访问器和直观转发方法没有机械补注释。
- 使用 JDK 21 执行 `./mvnw verify` 成功：服务身份 11 项、服务契约 5 项、Core 1,223 项
  （3 项按外部环境跳过）、CLI 143 项，合计 1,382 项无失败。
- 本轮范围的 `git diff --check` 通过；未执行提交、部署或数据库操作。
