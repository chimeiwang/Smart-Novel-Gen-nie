## 背景与目标

运行 `36426104126` 在上传约 94.7 MB 的 Agent 镜像时触发 1200 秒超时。
当前 SSH 管道同时承担传输、解压和 Docker 导入，无法从日志区分瓶颈。
本规格取代 [原上传规格](2026-07-16-production-image-upload-observability.md) 中
传输与导入共用命令及“归档只落 Runner”的约束，其余安全边界继续保持。

## 方案与边界

- 每张镜像仍在 Runner 独立归档，复用规则保持不变。
- 为本次上传创建权限受限的远端随机临时目录；传输到固定归档文件，接收端输出字节进度。
- 传输默认 1200 秒，校验受远端命令超时约束，Docker 导入默认 600 秒；日志分别标明开始、完成、耗时与退出码。
- 工作流上传步骤总预算为 180 分钟，覆盖最多三张镜像的串行阶段；单阶段失败仍立即停止，不因总预算放宽而延长单阶段等待。
- 校验远端归档 SHA-256 后才允许 `docker load --input`；远端导入自身也受超时约束。
- 容量预检计入远端归档，分别检查 Docker 目录与临时目录；共用文件系统时预留合计峰值。
- 成功或失败均清理本次临时归档；远端清理只允许本次随机目录内的固定文件，失败时保留原错误并报告残留路径。
- 保持严格 SSH 主机校验、生产串行发布、镜像标签校验、数据库只读门禁与现有应用回滚。
- 不修改业务实现、数据库结构、生产开关，不删除既有镜像、容器、卷或业务数据。

## 验收

- 行为测试覆盖正常分段顺序、传输失败不导入、校验失败不导入、导入失败及超时分别归因、临时归档清理。
- 运行部署脚本回归、工作流与 Compose 安全检查、Ruff、Shell 语法及 `git diff --check`。
- 推送通过验证的改动后，读取实际 Actions 运行与分阶段日志；区分脚本验证通过、诊断定位和生产发布成功。
