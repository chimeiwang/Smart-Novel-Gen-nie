# 根 AGENTS.md 职责治理

日期：2026-09-10

状态：已完成；仅整理开发指导及其文档入口。文档引用、命令、原具名迁移入口、规则保留与空白检查通过，独立复审未发现约束遗漏或授权范围变化。

## 背景与目标

根 `AGENTS.md` 混入产品功能清单、接口数量、部署提交、验收进度、数据库指纹和逐次授权记录，
与 `DOCS.md`、需求文档及专题规格重复。原“持久化改动必须更新本文件”的要求又促使历史记录持续追加。
视频 V0.1／V0.2 的摘要已与专题规格中的暂停状态不一致，说明多处维护同一事实会产生漂移。

恢复 `AGENTS.md` 的开发执行职责：让代理知道如何开始任务、遵守哪些边界、按需读什么和如何验证。
沿用产品基线整理规格中“只提取需要在每次开发任务中直接执行的规则”的原则。

## 设计与影响范围

- `AGENTS.md`：保留中文要求、事实核对、spec 优先、按任务必读入口、架构边界、数据与正式内容保护、
  Java 注释规则、前端约束、命令和验证要求；删除产品快照及发布流水，不弱化已有禁止事项。
- `DOCS.md`：明确执行规则、产品需求、架构、授权范围和验收证据的归属；用入口替代重复产品与迁移快照。
  后续只有通用开发规则改变时才修改根 `AGENTS.md`。
- `docs/DATA_CHANGE_AUTHORIZATIONS.md`：集中承接根文档中的具名数据变更授权范围、目标环境和排除项，
  链接原规格与执行证据；不复制发布进度和指纹，不把历史授权解释成当前实施指令。
- `docs/README.md`：登记上述入口及本规格，保留工作树中已有索引修改。
- `CLAUDE.md`：同步根文档职责与已失效的 Agent、数据库契约路径，不维护第二套规则。
- `docs/requirements/05-auth-billing-and-ops.md`：修正直接冲突的旧 Python 回滚、手机号生产授权说明，
  在迁移章节链接授权清单；其余领域需求不展开重写。
- 已有产品规则继续由 `docs/requirements/00-overview.md` 与 `01-05` 承载；已有发布、迁移和验收记录
  留在对应规格、运维手册及审计中，不再制造一份相同基线。

## 非目标与约束

- 不修改应用代码、数据库、服务配置、部署或供应商调用状态，不重新验收生产事实。
- 不恢复已暂停的视频实施，不扩大已有数据变更范围，不删除旧授权和小说成果保护要求。
- 保留已有未提交改动的语义，尤其是 Java 必要注释规则和视频范围限制。
- 不全仓重写历史文档；本规格取代 `2026-08-24-current-product-capability-baseline.md` 中要求根文件
  保留当前能力、缺口摘要的验收口径，后续以按需必读入口承载；根文档维护规则由 `DOCS.md` 明确。

## 验收

1. 根 `AGENTS.md` 中不再保留产品基线章节、API／CLI 数量、部署 SHA、结构指纹、逐次授权流水或验收进度。
2. 原架构、审核、幂等、数据完整性、数据库冻结、生产视频关闭及 V2 回滚禁令保留；具名例外可从必读入口追溯。
3. 所有移出信息均核对现有归属；独有授权边界迁入授权清单，已被新规格暂停的事项标明状态来源。
4. 本次新增和修改的文档链接有效、命令可定位，`git diff --check` 通过。
5. 只作一次性文档检查，不新增实现镜像测试，不运行与纯文档修改无关的应用测试。
