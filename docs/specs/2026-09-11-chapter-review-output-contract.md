# 正文复审输出格式故障定位与修复

## 目标与边界

定位线上整章一致性和编辑复审的 `MODEL_STRUCTURED_OUTPUT_INVALID`，以精确字段诊断和可复现
输入为依据修复输出协议。用户明确本次不实施自动纠错机制；不增加模型重试、不裁切 findings、
不猜测或改写复审结论，不修改正式章节、现有草案或历史冻结计划。

## 已知现场与待验证项

发布 `b7fc243f` 的 Run `cmtwv4pxq5d8tf8gqfjabsqti` 正文生成成功，两路复审分别出现
`schema_violation/type` 与 `schema_violation/maxItems`，均未超预算。旧失败回复被清空，
V2 日志遗漏安全字段路径，现存记录不能准确指认字段。隔离复现使用该 Run 的原冻结输入、
证据、输出 Schema 与模型参数；只输出安全路径、类型及数量元数据，不应用结果。

## 修复约束

- 补齐 V2 Schema 失败的安全 JSON Pointer 诊断；只允许 Schema 已声明字段与数组下标，
  不记录未知键、正文、供应商推理、密钥或原始错误文本。失败码、用量、终态和调用次数保持一致。
- 根据复现证据修正模型请求中的歧义和缺少的格式约束，完整保留业务评审与证据校验规则。
- 冻结提示词、profile 和计划如需调整必须新增版本，保留既有版本及恢复能力；不就地改历史资产。
- 不新增数据库结构，不引入复审纠正调用或自动恢复旧任务。

## 验收

1. 使用原冻结输入获得能定位到字段的复现证据；无法还原的旧回复不得伪称已还原。
2. 对实际错误形状建立离线回归，对有效输出和失败诊断分别验证。
3. 请求修正前后使用同一来源比较 Schema 校验结果，区分单次复现与稳定性保证。
4. 相关 Python 测试、Ruff、Mypy、资产指纹和历史快照兼容检查通过。
5. 如发布，单独记录提交、CI、部署与运行中资产验证，不以本地测试代替生产结果。
