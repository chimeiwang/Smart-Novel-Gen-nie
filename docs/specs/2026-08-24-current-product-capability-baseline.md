# 当前产品功能基线文档

日期：2026-08-24

状态：文档整理规格

基线提交：`c9afc95`

## 背景

当前产品事实分散在 Web 页面、Core API、Agent Service、CLI、数据库结构契约以及
`docs/requirements/01-05` 中。近期完成的章节影视化、逐镜生成和后期制作能力还没有完整进入总览；
同时，代码已实现、开发环境可运行、生产环境开放和历史兼容结构之间缺少统一状态标识。

Core 后续计划改写为 Java。如果没有一份产品层功能基线，迁移容易只对齐接口数量，却遗漏作者确认、
来源快照、并发冲突、功能开关和明确不支持项等真实产品语义。

## 当前项目事实

- Web 当前有 7 个路由页面和 1 个根布局，长篇工作区包含章节、创作资料、AI 协作和视频制作。
- Core OpenAPI 当前有 115 个路径、148 个公共操作，并另有 30 个不进入公共 OpenAPI 的内部操作。
- CLI 当前注册 125 个具体命令，不是对 148 个公共 API 的逐接口镜像。
- Agent 当前包含 5 个长篇核心 Agent、10 个可执行 CreativeOperation、4 个中短篇显式操作和
  2 个章节影视化工作流。
- 当前开发结构契约包含 85 张表、22 个枚举，指纹为
  `8aaa4d25c3cd3114bc8659330700a2eecdbcdefc7f3d83473c93c1baee576629`。
- 生产配置明确禁止开启 `VIDEO_PREVIEW_ENABLED`、视频后台调度和真实 Seedance 调用；P0-P3
  逐镜生成与后期制作迁移只获开发库授权。

## 目标

1. 把当前用户可见功能、自动化入口、内部支撑能力和历史兼容边界整理到一个产品文档。
2. 为每个功能域标明正常可用、依赖配置、仅开发环境、仅内部或已退役状态。
3. 写明关键业务规则、硬限制、当前缺口和明确非目标，避免把计划能力写成已上线能力。
4. 建立 Web、API、CLI、Agent 和数据契约的数量级追溯，作为 Java Core TDD 迁移的产品验收基线。
5. 在根 `AGENTS.md` 中保留一份面向开发代理的精简执行摘要，避免代理修改代码前遗漏产品模式、
   生产视频门禁和 Java 迁移边界。

## 非目标

- 不修改任何页面、API、Agent、CLI、数据库结构、配置或部署状态。
- 不开启生产视频功能，不执行开发库或生产库迁移。
- 不新增手机号注册、在线支付、协作、发布分发等功能。
- 不把 Backlog、历史规格或 Java 迁移计划中的未来方案写成当前承诺。
- 不逐字段复制 OpenAPI；产品文档描述用户能力和关键约束，接口细节仍由生成 OpenAPI 和代码负责。

## 文档设计

更新 `docs/requirements/00-overview.md`，使其成为当前产品功能基线，至少包含：

1. 产品定位、成熟度判断和状态口径；
2. 用户角色、工作区模式、页面入口和端到端流程；
3. 认证、项目、章节、中短篇、资料库、Agent、审核、质量、视频、计费、CLI 和运维功能；
4. 正式写入、版本、来源绑定、幂等、并发和任务恢复等横向规则；
5. 商业化、协作、写作、视频、CLI 和运行环境限制；
6. 当前接口与数据基线，以及 Java 迁移必须保持的产品不变量。

根 `AGENTS.md` 只提取需要在每次开发任务中直接执行的规则，并链接回产品文档；不复制完整功能清单，
也不把当前数量快照伪装成永不变化的架构常量。

## 影响范围

仍按 `DOCS.md` 的项目事实优先级处理并修正文档。

## 验收标准

1. 两种创作模式及其差异和硬限制均有明确说明。
2. 长篇章节影视化完整主链被列出，并明确生产关闭、开发库授权和供应商限制。
3. 125 个 CLI 命令的覆盖范围与非全量 API 镜像事实被如实说明。
4. 手机号、账号恢复、在线支付、协作、移动端、图片生成、TTS 等当前缺口被明确列出。
5. 文档能作为 Java Core 重写的产品验收入口，同时不改变任何运行状态。
6. 文档中的数量与当前 OpenAPI、CLI 注册表和结构契约一致。
7. 根 `AGENTS.md` 能让后续代理在修改前识别两种创作模式、作者确认不变量、视频仅开发环境、
   当前商业化缺口和先迁移后增功能的边界，并要求详细判断回读产品文档。
