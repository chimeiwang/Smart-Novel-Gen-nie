用户本轮要求完成 V0.1 和 V0.2，并明确当前相关视频功能没有历史数据，授权按需要修改相关数据库字段。该授权用于本次视频定妆、单镜试制与恢复闭环；不扩展为修改小说正文、账号、计费历史或开放生产视频。

## 1. 交付范围

- 角色、地点、道具在现有设定入口管理单图定妆、服装／场景变体、候选批准和历史；原视频工作台复用编辑器，精确镜头引用保持不变。
- 服务端禁止删除被视觉槽使用的设定，覆盖真实 PostgreSQL 并发与归属规则。
- 候选保存增加必填 `expectedRevision`：新槽为 0，已有槽使用打开编辑器时冻结的 revision；冲突回读但保留本地输入，作者明确选择后才能基于新版继续提交。完整相同候选的重复请求可无副作用回读。
- Seedance 2.5 首批试制限定图片参考模式、4～12 秒、720p、最多 20 个图片参考（含关键帧）；这是本产品受控首批范围，不是供应商完整能力上限。禁止把首尾帧角色与多模态混用；正式声明 reference 模式。
- `SEEDANCE_EXECUTION_MODE` 默认 `simulated`。readiness、任务清单、内部提交／查询冻结 executionMode；模拟结果显示不调用即梦、不收费，生成带模拟标记的可播放占位 MP4。只有显式 live 配置才允许独立真实函数运行，并要求本次 feeConfirmed；不做商业充值、完整预留结算或批量生成。
- 提交未知独立展示与保留，不作为普通失败重试；后端同样禁止从未知结果直接普通重试，避免界面绕过。
- 已成功的供应商结果在归档失败后继续恢复同一 providerTaskId，不重新生成。失败、重启、重复完成不产生多个逻辑 Take。
- 渲染／导出持续轮询、手动刷新和离开清理；关键帧／音频上传须有作者显式权利确认。
- 素材先真实探测、归档后公开成功；提供可播放 Take、确认采用及公开接口回读证据。

## 2. 数据与契约

优先复用当前结构。用户允许重构相关字段，不要求为假设的旧视频行增加复杂兼容；但代码仓内既有契约与结构改变仍须同步，任务输入在新任务运行期间保持冻结。

若需要 DDL，单独增加具名迁移，先在隔离 PostgreSQL 验证，再按实际开发环境执行并重新导出 schema contract；不由应用启动自动迁移，不修改无关业务表。本轮没有生产发布请求，不执行生产 DDL或开启生产视频。

公共字段先修改 Python/Pydantic，再生成 TypeScript 与 Java 契约。Agent 协议从 Python 共享模型导出。最小健康上下文、非视频设定操作与跨项目归属不能退化。

## 3. 验证

1. 设定创建／单图候选／批准／变体／历史／正式镜头绑定的浏览器与 PostgreSQL 闭环。
2. 设定删除与视觉引用创建的两种竞争顺序、跨用户／小说／项目拒绝。
3. 正确与非法 Seedance 新请求、未知提交、显式重试、连续观察。
4. 供应商创建一次、首次归档失败、同任务恢复并只产生一个 Take；恢复观察与进程重启后收敛。
5. 相关前端测试、typecheck、lint；Java JUnit 与完整 Maven verify；Python pytest、Ruff、Mypy；契约生成与 api:check。
6. 模拟必须不依赖 API Key、不访问供应商，且可跨 Agent 重启查询：providerTaskId 与本地 taskId 确定绑定。特殊模拟输出标识仅由 Core 在冻结 simulated 模式精确匹配后进入本地媒体生成分支，不得放宽 live 网络地址策略。真实画质与计费验收由用户明确延期，不作为本轮完成条件。
