## 1. 产品要交付什么

InkForge 视频功能的核心交付物是：作者基于自己的小说，持续制作角色、声音和剧情衔接稳定的系列短片；能够预览、修改、控制成本，并导出可以交付的成片。

面向的首发用户是独立小说作者或由单一账号操作的创作者。作者理解自己的故事，但不必懂模型参数、镜头协议或专业剪辑软件。团队分工与企业工作空间不作为首发依赖。

建议首发默认使用中文、9:16、每集约 60～120 秒的风格化叙事模板，保留明确的画幅和时长选择。该范围用于组织试制与用户测试，属于产品建议，不是新增硬限制。真人感与漫剧共用制作流程，但必须分别验收，不能以一种风格的样片证明另一种已成熟。

生产级的含义有五条：

1. **连续出片**：做完第一集后，下一集能继承角色、声音、场景与必要剧情状态。
2. **可控质量**：作者能在花费较少时判断故事与画面，在花费较多后定位并修好具体问题。
3. **可控花费**：生成前知道本次最多承担多少费用，失败和重试有明确账务结果。
4. **可靠恢复**：刷新、断网、服务重启不丢已保存编辑、不重复生成或扣费、不遗失已生成素材。
5. **可交付**：作者在产品内看到与导出一致的画面、声音和字幕，能拿到完整文件和版本记录。

首发验收单位为“同一个作者连续做成三集，并完成一次中途修订”，单镜成功和单集样片只作为前置证据。本文提出的新目标将取代早期总方案以制作包预览和短片段试制为首发终点的规划；旧规格的来源冻结、作者确认与供应商边界仍有效，评审通过前不改写当前产品基线。

## 2. 当前已有的基础与实际差距

当前生产关闭结论来自源码门禁和仓内发布记录，本轮未重新核验服务器实时配置。现有制作链为：单章快照 → 人工审镜 → 章节内分集 → 视觉参考 → 提示词 → 关键帧 → Take → 粗剪 → 声音字幕 → 导出。

| 领域 | 当前可确认的实现 | 达到目标仍需补齐 |
| --- | --- | --- |
| 小说改编 | 完整单章快照、戏剧节拍、镜头候选、作者确认、修订 | 剧集计划、跨章节来源、独立银幕剧本、跨集连续性 |
| 角色和场景 | 视觉槽位、上传定妆图、变体、正式版本、逐镜绑定 | 面向全剧的资产工作区、基础图片生成、多视角定妆、状态继承 |
| 视频生成 | 单镜显式任务、冻结输入、候选 Take、比较与采用 | 单镜报价、单集预算、受控批量、作者取消、异常对账 |
| 结果保存 | 先归档受控存储，再登记成功和不可变 Take | 归档失败独立恢复、容量和保留策略、恢复演练 |
| 剪辑声音 | 基础裁切、硬切／淡黑、上传音轨、字幕、MP4 导出 | 整集实时审片、基础配音、原声可控、分句返工、字幕对齐 |
| 版本 | 方案、提示词、素材、Take、剪辑、声音与导出版本冻结 | 清晰的修订影响说明、跨版本镜头复用、工作草稿恢复 |
| 运行 | Core 权威耐久任务；拆镜／提示词已接入 V2 Step | 真实视频供应商、媒体处理资源、渲染账务和生产端到端验收 |
| 产品入口 | 当前章节内八步工作台，默认创建 series 项目 | 以整部剧与每一集为中心的导航、跨集进度、下一步指引 |

保留现有的候选采用、版本冻结、归属校验和权威任务机制。新产品流程应在这些基础上演进。

### 2.1 上线前必须处理的源码风险

以下是本次源码核对结果，不宣称已在真实浏览器或付费环境复现：

| 风险 | 用户后果 | 产品验收要求 |
| --- | --- | --- |
| 渲染／导出使用单次定时刷新，任务仍活跃时未必继续安排刷新；渲染中手工刷新被禁用 | 页面长期显示生成中，作者不知道是否可以继续 | 持续读取权威状态；断网重连与手工刷新均可恢复；显示最后更新时间 |
| 提示词、粗剪和声音编辑存在组件本地状态及切换重置 | 切镜、切集、切步骤或刷新可能丢未保存工作 | 工作草稿自动保存；明确保存状态；冲突时保留双方内容；重新进入恢复上下文 |
| 关键帧／音频上传路径自动把权利状态设为 confirmed | 产品替作者作出本应由本人确认的声明 | 上传与权利确认分开；作者显式确认；批量声明列清覆盖素材 |
| submission_unknown 被当作普通失败并允许重试 | 结果未核实便再次付费 | 独立“提交待核查”状态；不能用普通重试按钮诱导再次付费 |
| 归档失败变为普通 failed，重试复制输入并新建供应商生成任务 | 已生成视频仅因下载失败而重新收费 | 优先恢复已有供应商结果；只有明确重新生成才新建计费任务 |
| 逐镜渲染只有 usage 元数据，未接视频报价、预算预留与结算账本 | 作者和平台都无法可靠控制单集成本 | 补齐渲染专用计量、报价、预留、结算和对账；不混同已实现的文本模型计费 |
| 当前 FFmpeg 在系统临时目录先生成整集文件，生产 Core 的 /tmp 为 32 MiB | 开关开启后仍可能因媒体空间不足无法出片 | 提供经过容量计算的媒体工作目录、隔离资源与磁盘不足恢复方案 |

## 3. 最重要的产品调整：以“剧集”组织生产

### 3.1 分集应当先于逐镜生产

当前是在单章镜头中划集尾。目标产品应先让作者确定这几集讲什么，再决定每集怎样拍：

**选择小说来源 → 剧集计划与分集剧本 → 角色／场景定稿 → 分镜预演 → 镜头生成与选片 → 整集审片交付。**

一章可以改成多集，一集也可以组合多个章节的片段。第一集可只做一小段故事；系统不要求一次理解或制作整本小说。

新增的“银幕剧本”是独立改编成果：包含场景、可见动作、对白／旁白、情绪和叙事目的。小说中的心理活动可以被改成动作、对白或旁白，但改编增删要有可审阅说明，不能回写小说正文。

### 3.2 作者应能明确掌握六类成果

| 产品对象 | 作者需要掌握的信息 |
| --- | --- |
| 剧集项目 | 风格、画幅、受众、集数计划、预算、交付进度 |
| 来源与改编剧本 | 使用哪些章节和版本、保留／合并／省略了什么、哪些是新增视听表达 |
| 系列设定库 | 角色身份、服装、场景、道具、声音，以及适用范围 |
| 分集与镜头 | 本集冲突、观众应知道的信息、分集结尾、镜头动作和声音 |
| 候选素材与采用结果 | 每次生成用了什么输入、花费多少、为何采用或放弃 |
| 审片与交付版本 | 哪些镜头、声音、字幕进入了这版成片，有哪些待修问题 |

这是产品语义，不是数据库表设计。后续应先核对现有 schema，新增持久化需求单独形成具名迁移方案；不能把所有新语义塞入旧章节字段或旧 VideoScene 域。

### 3.3 连续剧需要两种不同的继承

- **长期身份**：角色脸型、基础造型、音色、场景结构与整体画风，来自系列设定版本。
- **剧情状态**：本集服装、伤势、持有物、所在位置、已知信息和关系变化，来自被作者确认的连续性记录。

每集冻结使用的版本。新一集从前集被采用的结尾状态生成候选；回忆、倒叙和有意换装由作者明确标注，不按物理集序盲目继承。系统只提示冲突，艺术性选择由作者决定。

## 4. 作者的完整工作流程

### 4.1 创建剧集与改编方案

作者从小说选择若干章节或段落，选择风格、画幅、单集目标时长、对白／旁白倾向与单集预算。系统生成分集提案：每集核心事件、开头情境、冲突推进、结尾，以及来源与改编差异。

作者可重排、合并或拆分剧情，明确本次只制作哪些集。确认后形成独立剧本版本。先显示故事是否讲清楚，再在检查器展开 Scene、Beat 等专业信息。

集尾悬念、开场吸引力、平均镜头长度属于建议，不能作为固定公式强迫每部作品采用。

### 4.2 定妆与声音

复用小说已有角色、地点与道具，在设定卡增加视觉定妆和声音入口，关联现有视频视觉版本。图片可通过符合供应商规则的上传、已有 Take 抽帧或另行接入图片模型形成候选；视频工作区与设定卡显示同一份权威版本。

角色至少提供可复用的正面／侧面或按当前镜头所需的多视角参考、主要服装与辨识特征。系统显示定妆对比和适用集范围，作者批准后再成为正式素材。图像参考是生成依据，不承诺模型必然保持一致，仍需实际审片。

声音优先验证 Seedance 2.5 原生音视频和音频参考，保存角色声音版本、试音、读音要求及本集对白。实际声音与台词需审片核对；必要时重新编辑相关音视频或采用明确静音后的后期配音。独立 TTS 是按连续三集验收结果选择的补救能力，声音克隆不列入首发。

面向普通作者的首发必须提供可完成的素材与声音获取路径，不预先绑定额外图片或 TTS 供应商。受控内测可导入外部素材，公开承诺应准确说明内置能力和作者准备要求；不能把 Seedance 视频生成能力描述成独立图片生成或分轨配音接口。

### 4.3 分镜预演与代表镜头试制

确认剧本后生成可编辑分镜板，每镜展示：画面、主要动作、对白／旁白、时长、角色／场景引用、预计成本和潜在难点。

先用分镜静帧、临时或正式声音及字幕组成预演片，检查节奏与信息是否完整。预演明确标记为草稿，与真实视频成片区分；静帧生成或配音如计费，仍须预先报价。

选择少量代表镜头试制：角色近景、双人同框、场景切换和一处本作品关键动作。确认表现和实际成本后再扩大生成。高难度动作、长对白、多角色互动应提供拆镜或改拍建议，不能承诺一定成功。

### 4.4 生成与选片

可以对单镜或同集内连续镜头组成的叙事片段生成候选，再次生成或修改参考后生成新版本；界面明确输入差异、范围和收费。Seedance 2.5 单次上限是能力边界，不要求每次凑满 30 秒；剪辑采用区间按实际视频确认，不能把计划切点直接当成真实切点。

支持作者显式选择一组已准备镜头，审核生成清单与总费用上限后启动批量。默认每镜一次尝试；可由作者设定最多尝试次数与总预算。遇到问题、限流、余额不足或不确定提交时暂停相关任务，不能为了追求完整率自动花完预算。

候选比较提供同步播放、逐帧查看和“角色／动作／台词／连续性”等问题标记。作者选择采用结果；机器检查给出定位与证据，不自动把最高分视频设为正式结果。

批量操作保存冻结清单，刷新和服务重启不产生第二份工作。出现预算或输入变更时，由作者查看变化后续作，不静默扩单。

### 4.5 剪辑、声音与交付

提供可连续播放的整集时间线、裁切与基础转场、逐片段原声静音／增益、对白／旁白／环境／音乐音轨、字幕编辑。可以只换一句配音、一个字幕或一个镜头，其他已采用内容保持稳定。

对白驱动片段优先使用确认后的台词和配音时长组织镜头；旁白漫剧可使用旁白与画面组合。口型同步能力只有通过目标供应商实测才能提供；若未实现，产品明确限定可交付表现形式，不宣传为已支持自然对白表演。

整集预览与导出使用同一冻结时间线语义，显示实际画面、混音、字幕和裁切。低清预览和高清输出有明确标识，不把导出分辨率等同于素材原生清晰度。

导出前检查缺片、越界字幕、黑屏、无意静音、明显音画漂移、画幅和字幕安全区域；软质量问题允许作者确认接受。交付包包含 MP4、可单独下载的字幕、封面及镜头／素材版本清单。使用者可导出原始候选素材继续精剪；高级剪辑工程互通另做规格。

“导出完成”只表示文件可交付。平台发布、分发、内容审核与平台运营结果分别标记，首发不承诺自动完成。

## 5. 工作台信息架构

主入口从“当前章节视频页”提升为小说下的“剧集制作”。进入后先看到各集的故事摘要、制作阶段、待处理问题、累计花费与最近交付版本。

工作区布局遵循 `DESIGN.md`：左侧是分集与共享资产导航，中间是剧本／分镜／播放器或时间线，右侧是所选对象检查器，任务进度与费用保留稳定入口。

每集主流程用五个面向作者的阶段：

| 阶段 | 主区内容 | 主要决定 |
| --- | --- | --- |
| 剧本 | 改编方案、对白、来源差异 | 本集讲什么 |
| 定妆 | 角色、场景、服装、声音 | 用什么形象与声音 |
| 分镜 | 分镜板与有声预演 | 怎样拍、是否值得进入生成 |
| 制作 | 候选播放、比较、问题和费用 | 哪个结果可采用、哪里需重做 |
| 成片 | 时间线、音轨、字幕和整集播放 | 是否可交付 |

阶段可回访，不能作为强制单向向导。根据当前状态恢复到作者离开的位置；顶部只显示具体下一步，例如“3 个镜头缺参考图”“2 个候选待选”，而不是要求作者自行理解八个技术页面。

提示词、参考强度、哈希和模型参数收进专业检查器。普通作者可以表达“动作慢一点”“保留这个角色造型”，先查看修改候选和影响，再决定是否应用或付费生成。

系统可以在一次人工确认中列清一组素材或镜头的差异与采用对象，减少重复点击；不能把批量确认改成隐式自动采用。

## 6. 修订必须支持局部工作与影响预览

| 作者修改 | 应有行为 |
| --- | --- |
| 小说正文后来更新 | 已交付视频保持原来源；提示可比较新旧正文；选择后创建新改编版本 |
| 修改一个镜头的动作 | 新建该镜头候选；展示相关提示词、关键帧、Take 和剪辑引用的影响 |
| 更新角色定妆 | 作者选适用范围；旧集、旧素材和正在运行任务继续绑定原版本 |
| 更换采用 Take | 当前剪辑提示可更新该片段；保留裁切或提示不兼容；原导出可继续下载 |
| 修改一句台词 | 优先局部重配／改字幕；检查该镜头的口型、表演与原声依赖，必要时重做对应 Take；时长改变时提示后续时间线影响 |
| 调整分集边界 | 给出新增／移动镜头、过期声音、预算变化，作者确认后创建新版本 |

建立稳定的逻辑镜头与不可变镜头版本映射。只有确认依赖未变、素材完整且引用兼容的结果才可复用；不能仅因镜号相同就套用旧 Take。复用与有意重新生成是不同操作。

重建意味着可还原当时输入、采用素材与成片；不保证同样提示词重新调用模型能生成相同像素。

## 7. 成本、失败与商业规则

### 7.1 生成前的费用承诺

报价至少包含：操作和目标镜头、时长／清晰度／音频、供应商与价目版本、本次积分或金额上限、已花费／预留／可用预算、预计等待区间和报价有效期。预估来自实测或历史数据；没有数据时显示暂无可靠估计，不显示假进度。

Core 按用户与单集预算原子预留，防止多个页面或任务同时超支。批量开始后，实际已花费加在途费用承诺不得超过作者批准上限；不能可靠约束单任务最高成本时，不能开放有确定总价承诺的批量执行。

文本改编、图片生成、配音、视频生成、存储与导出分别记录计量规则，再在作者界面汇总。供应商成本、平台积分和现金不能共用含混字段。供应商涨价或输出参数变化时重新报价，不静默扣新价格。

单集实际成本必须包含被放弃的候选和已发生费用的失败尝试。运营重点看“每分钟被作者采用的成片成本”，不能只展示每次模型调用的单价。

成本示例只用于解释：90 秒成片如果最终采用 18 个各 5 秒片段，平均每个片段生成 3 次，则视频生成量约为 270 秒，再加其他步骤成本；供应商可能使用 token 等计价方式，不能直接把生成秒数当账单。本文不填未核实的供应商价格或毛利率。

### 7.2 状态与作者能采取的行动

| 状态 | 作者看到的结果与操作 | 费用处理原则 |
| --- | --- | --- |
| 未发到供应商 | 可以取消 | 释放尚未消耗的预留 |
| 供应商排队／执行中 | 显示真实状态；取消能力按实测支持 | 不承诺任何状态都能取消或退款 |
| 提交结果未知 | 显示待核查，提供任务凭据和支持入口 | 保留待对账事实；不自动重提、不按零消耗结算 |
| 供应商成功、归档失败 | 显示视频已生成、正在恢复文件 | 只恢复下载／归档，不产生新视频生成费用 |
| 明确生成失败 | 说明失败原因及预留处理；重新生成另行报价 | 已发生供应商成本与用户收费分别处理 |
| 成功但作者不满意 | 可保留／放弃／修改后再次生成 | 原尝试有成本；新尝试显式收费 |
| InkForge 自身故障 | 给可跟踪的问题和恢复进展 | 平台补偿政策独立记账，不把平台损失改成供应商零成本 |

结果未知必须有人工处理负责人和审计入口，记录结论与可见时间；不能永久停在技术错误。公开付费前明确服务时段、处理目标与补偿政策，内测收集处理时长后确定对外承诺。

若用户已理解风险仍选择在待核查期间重新生成，需要独立费用确认并保留旧任务对账，不能复用“免费重试”的语义。

### 7.3 商业开放的最小闭环

有限邀测可以使用明确额度的测试积分。公开售卖前必须具备用户可查看的费用明细、余额和补偿入口，以及可靠的收款／充值或其他已验收结算流程；项目当前在线支付缺口不能被视频功能绕过去。

首发采用用量与单集预算控制，不在缺乏真实成本样本时推出无限生成承诺。账号额度、共享供应商配额与平台总成本均须有上限和告警。

## 8. 生产发布必备条件

### 8.1 内容和资产

- 小说、上传图片、声音、音乐分别记录权利来源和本人确认；生成素材记录供应商与生成凭据，不能只记录一个泛化勾选。
- 对确有问题的素材停止新生成、引用和下载，并支持作者申诉与更换；保留必要审计关系，不能直接删掉仍被交付版本引用的来源。
- 明确素材容量、保留期限、作者删除请求和已交付版本的关系。已采用、已交付依赖与可清理的未采用候选分别管理；任何自动清理先提示其影响并遵守已公布策略。
- 发布前核对适用的生成内容标识、供应商规则及目标分发平台要求，形成实际检查项；本规划不作法律结论，也不把素材声明描述为自动版权审核。

### 8.2 供应商能力

以真实 API 和当前账号权限建立能力档案：精确模型 ID、地区、输入类型、时长、画幅、清晰度、音频、参考图语义、取消、任务保存期限、价格和并发额度。

本轮后续已读到国内官方创建接口、2.5 提示词指南、计费与取消正文，确认模型支持多模态参考、首尾帧、编辑与延长。当前代码默认 `doubao-seedance-2-5-260628` 的精确 ID 仍须账户模型清单复验；账号开通、配额和真实输出尚未验证。现有适配器把所有图片发送为 `reference_image`，需新增独立首尾帧模式及互斥校验，不能把当前模式的文字首末状态标成强约束首尾帧。

首发指定火山方舟 Seedance 2.5，先验证一组输出配置；服务端保留替换边界，用户无需先面对模型市场。模型升级作为显式版本切换，旧结果继续可读，不静默重跑历史镜头。

### 8.3 运行和恢复

- Core/PostgreSQL 继续拥有正式成果、任务与账务；Agent 消费冻结输入、执行模型，不直接访问数据库。
- 拆镜与提示词的 V2 隔离验收只证明对应文本模型阶段；Seedance 生成、归档、关键帧与成片导出须分别验证，不能用操作接线数量替代全制作链证据。
- 媒体处理采用独立、可限额的工作目录与执行资源，依据源素材、代理预览、中间文件和输出的同时占用计算容量；不得沿用 32 MiB 系统临时空间当成成片工作盘。
- 生成、归档、抽帧和导出各自有超时、并发、容量与重试规则。长媒体工作不能拖垮小说写作、登录与健康查询。
- 归档文件校验真实格式、可解码性、时长及哈希；媒体输出先完整落盘／归档再公布成功，浏览器不依赖供应商临时 URL。
- 压测覆盖计划邀测峰值和媒体最坏任务；仅凭小文件成功或代码测试通过不能放量。首批并发和配额以实测决定，不要求先迁移复杂部署平台。
- 保留关新建、停付费派发的紧急开关；停机后仍能查询旧任务、完成必要归档与账务收敛、下载原成果。
- 监测卡住任务、供应商失败、归档失败、预算异常、待对账、磁盘空间、导出队列和备份恢复；每类异常有具体处置步骤。

### 8.4 授权与兼容

当前 production 环境主动拒绝开启视频；既有 P0／P1-P3 只获开发库迁移授权。正式发布需要独立的兼容代码、具名生产迁移、备份恢复、契约复验、供应商小流量验证与开放方案。

本文不改变已有生产 V2 数据的保护规则；不能执行已禁止的 DDL rollback，不能回退到 V1-only Python Core，也不恢复旧 VideoScene／VideoGenerationTask 公共生产语义。

## 9. 按可验收成果推进

本规划不以现有 P0～P3 名称表示新工作的完成程度。采用以下里程碑；未估算人力和真实供应商反馈前，不承诺日历日期。

| 里程碑 | 必须交付 | 退出条件 |
| --- | --- | --- |
| A：验证制作路线 | 真实账号能力档案、代表镜头、同角色跨镜测试、声音方案、完整费用样本；修正明确的状态／草稿／权利风险 | 找到可交付的风格与参数组合；成本和主要失败可解释；付费验证按既有边界执行 |
| B：作者独立完成一集 | 分集剧本、设定定妆、明确素材获取路径、原生音视频与声音参考、有声预演、生成选片、整集预览和导出 | 新作者按产品指引完成一集，无需开发者手工改数据或准备必须素材；不足部分有可用补救路径 |
| C：连续三集与局部返工 | 全剧入口、跨章改编、资产继承、连续性检查、稳定镜头映射、修订影响与复用 | 三集连续交付；只改一个镜头／一句台词可完成新版本，不牵连其他成果 |
| D：受限生产邀测 | 渲染计费闭环、恢复归档、异常对账、媒体容量、访问控制、支持流程及经授权生产发布 | 真实付费与故障恢复证据完整；少量白名单作者在额度内完成三集任务 |
| E：公开商业首发 | B～D 的完整闭环、收款和补偿、清晰使用范围、基于实测的配额与价格 | 用户与运营指标达标后逐步扩大额度；遇到异常可停止新任务并保全已得成果 |

里程碑 A 即使还没有正式报价系统，每次真实付费试制也须先明确人工预算上限、最大尝试次数和凭据登记方式，不能无限试到满意。

保留到后续的范围：多人协作、移动端、声音克隆、角色训练、复杂区域修复、复杂口型编辑、高级调色／特效、无限时长项目、多供应商市场、自动平台发布与运营。单镜重新生成与替换属于首发必要能力；Seedance 2.5 时间戳音视频编辑和延长纳入目标范围，按独立场景验收后开放，不与高级合成能力混淆。

## 10. 首发验收与衡量

以下数量与阈值是**建议的首次验收目标**，不是当前观测结果或对外服务承诺；试制后可有证据地调整，并说明取舍。

### 10.1 必须通过的产品与可靠性场景

| 场景 | 通过标准 |
| --- | --- |
| 新作者上手 | 5 名目标作者中至少 4 名在指引内完成连续 3 集；无需开发者代操作，供应商等待与人工操作分别记录 |
| 故事表达 | 至少两名未读原著的评审观看后，每集能回答预先列明的主要角色、核心冲突和关键结果；作者确认没有未同意的关键剧情改写 |
| 连续性 | 三集复用主角、服装变化、场景、声音；明确的身份错位、关键道具矛盾和非意图音色改变全部处理或被作者明确接受 |
| 局部返工 | 重做一个镜头和一句对白，不重新生成其他已接受素材；旧成片仍可下载；新引用与费用可追溯 |
| 编辑恢复 | 各阶段编辑后切镜、切集、切步骤、刷新和重新登录，已显示保存成功的内容恢复一致；未保存或冲突状态不被隐瞒 |
| 重复与不确定请求 | 重复点击、回包丢失、重复回调、重启注入均无非授权重复生成／重复扣费；提交不确定进入待核查 |
| 成功后归档中断 | 故意使第一次归档失败，恢复同一供应商结果；供应商创建次数不增加，最终仅一份逻辑 Take |
| 预算边界 | 多页面／多任务同时提交、余额不足、价格变化与重试都不突破用户批准的在途加已花费上限 |
| 整集交付 | 无占位镜头；音画完整；字幕和裁切与预览一致；下载后可完整解码；输出清单可回溯 |
| 历史保护 | 改正文、换角色图、更新模型或重新分集后，旧任务输入和旧成片不变；跨账号不可读写 |
| 发布与恢复 | 关闭新任务后在途任务按策略收敛；备份恢复可重新关联账务、素材和交付；最坏媒体任务不破坏写作链 |

账号身份与资源归属、账务、非授权重复付费及数据丢失问题为发布阻断。画风、镜头节奏等审美评价不替代作者选择。

### 10.2 需要持续采集的指标

- 核心结果：每周完成并导出至少一集的创作者数，以及首次创作者三集完成率。
- 制作效率：首次可用预演用时、首集与后续集人工操作时长；模型等待时间独立统计。
- 成片成本：总实际费用／被采用成片分钟数，包含放弃候选、失败费用及相关图片／配音成本；同时看中位数与 P90。
- 可用素材率：被作者采用的候选数／已成功归档的候选数，按风格、镜头类型和模型版本分组；另报供应商技术成功率。
- 返工效率：每个被采用镜头的尝试次数、一次台词／镜头修改的额外费用和时间、跨集可复用资产比例。
- 可靠性：归档与导出成功率、卡住任务数、待对账金额及年龄、重复扣费与丢编辑事件数。

不使用“总生成次数”作为主要成功指标。先用邀测的真实数据建立价格、容量与处理时效目标，再扩张。

## 11. 后续实施影响

后续工作需分别形成可实现的规格：

1. 剧集、跨章来源、独立改编剧本、连续性与修订依赖的产品／持久化契约。
2. 复用设定的多图定妆、声音参考及画风版本；Seedance 2.5 模式、供应商素材凭据、审核与费用契约；按需要补充图片／TTS 能力。
3. 视频报价、预算、批量清单、取消、归档恢复和对账状态机。
4. 工作草稿、整集预览、原声控制、字幕与交付包。
5. 媒体容量和生产开放、数据库具名晋升、隔离环境与真实供应商验收。

实现时先改权威 Python/Pydantic 公共契约，再生成客户端并实现 Java；Agent 新模型步骤纳入既有耐久执行边界。新增 schema 先更新 spec 和 AGENTS 授权记录，不以本规划替代批准。

验证按变更范围执行前端相关测试、typecheck、lint；Java JUnit 与提交前 Maven verify；Python pytest、Ruff、共享工作流 Mypy；数据库 PostgreSQL 契约／并发测试；部署安全检查与真实媒体、浏览器、故障恢复验收。生产级判断以真实流程证据为准。
