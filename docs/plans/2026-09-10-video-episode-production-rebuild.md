# 剧集制作重构修改计划

日期：2026-09-10

状态：P0～P4 的仓内实现和本地隔离验收已经完成。新 Episode 前端、公共 API、普通 CLI、关键帧、simulated MP4 和基础后期已经落地；A／B／C 组合 E2E、完整 `mvnw verify` 及仓内全量门禁已经通过。真实 Seedance、服务器物理退役和生产开放继续排除。

依据：[产品设计](../specs/2026-09-09-video-production-redesign.md)、[实施规格](../specs/2026-09-10-video-episode-production-implementation.md)。本计划替代原 V0.1／V0.2 的执行顺序和工时估算。

## 1. 完成后作者得到什么

作者可以在小说下按集制作：跨章节取材，起草并确认单集剧本，生成和审核分镜，明确采用定妆与视频素材，完成基础剪辑和模拟成片。修改一场戏时，系统保留已有成果，并指出本集及后续集需要复核的部分。

三个验收场景沿用已确认设计：第一集《雨夜交信》、承接它的第二集《拆信》、第一集改为收回信后处理第二集承接。虚构固定素材用于验证流程，不证明真实模型画质和声音效果。

不包含生产发布、真实付费视频试制、商业结算、完整声音引擎或高级剪辑。没有给旧视频接口兼容性增加产品要求；共享小说成果、审核与执行证据仍须保全。

## 7. 并行与整合方式

主顺序：P0 → P1 → P2 → P3 → P4。每批按领域接口划分 Java／数据、Python 契约与 Agent、Web 三条可并行工作线，指定一处统一生成和整合契约产物。

- Java／数据负责事务、归属、幂等、持久化与媒体使用关系。
- Python／Agent 负责公共 Pydantic、共享输出 Schema、V2 模型步骤与受控响应。
- Web 负责真实业务状态对应的编辑、确认、导航和复核。
- 整合负责人串联迁移、生成代码、公共 CLI、浏览器验收及文档，不允许各工作线自行增加另一份状态权威。

跨服务契约未确定之前不并行猜字段；迁移执行、代码生成和共用文件编辑按依赖串行。旧写入口的关闭跟随对应新入口开放，不等最后集中处理。
