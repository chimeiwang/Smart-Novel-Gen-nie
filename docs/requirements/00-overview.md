## 2. 产品结论

InkForge 当前是一套面向中文小说作者的桌面优先创作工作台，核心不是“让 AI 自动写完整本书”，而是把
作品资料、写作过程、AI 草案、作者审核和版本追踪放进同一条受控链路。

当前产品已经形成三条主要能力线：

- 中短篇：起始素材 → 蓝图 → 正文 → 不可变版本 → AI 候选或全文检查；
- 长篇连载：项目与章节 → 设定和大纲 → AI 会话与多 Agent → 草案审核 → 章节终检；
- 长篇章节影视化：章节快照 → 电影化拆镜 → 分集 → 视觉稳定 → 逐镜提示词 → 逐镜生成 → 后期输出。

其中前两条属于正常产品实现；影视化全链在代码和开发库中已实现，但生产配置明确禁止开启视频写入、
后台调度和真实 Seedance 调用。因此当前不能把影视化描述为已在线上开放的商业能力。

从成熟度看，InkForge 已经具备较完整的创作领域和耐久任务基础，但还不是成熟商业 SaaS：手机号认证代码、
服务器开发库迁移、公开联系渠道和真实短信送达测试已完成，正式库迁移与生产开放已获批准但仍在受控执行，
账号找回、在线支付、管理员后台、多人协作、移动端和内容发布分发仍未完成。

## 3. 功能状态口径

| 状态 | 含义 |
| --- | --- |
| 通用实现 | 当前代码存在完整用户入口，且没有开发环境专用开关；是否已部署仍需单独验收。 |
| 条件可用 | 功能已实现，但依赖 Redis、模型、Embedding、FFmpeg 等配置或外部服务。 |
| 仅开发环境 | 代码与开发库已实现，但生产配置或迁移授权明确禁止开放。 |
| 内部能力 | 只服务 Core、Agent、调试或运维，不是普通作者的独立产品入口。 |
| 已退役 | 不再允许创建新业务对象，只保留历史数据读取或终态收敛。 |

## 4. 产品角色与权限

| 角色 | 当前能力 |
| --- | --- |
| 未登录访客 | 查看官网、进入登录或注册。 |
| 已登录作者 | 管理自己的小说、章节、资料、文风、AI 任务、草案、积分；在允许环境使用视频制作。 |
| CLI 操作者 | 使用同一作者账号调用受支持的 Core 公共接口，不能绕过权限、审核、CAS 或功能开关。 |
| 开发/运维人员 | 查看健康状态；在显式启用后查看工作流事件；使用日志和 LangGraph Studio 调试。 |

当前没有以下产品角色：

- 管理员后台角色；
- 编辑、审稿人或协作者角色；
- 团队、组织、工作空间成员；
- 只读分享访客；
- 付费套餐或订阅管理员。

所有小说级资源都必须沿归属关系校验到当前作者。知道资源 ID 不代表有权读取或修改。

## 5. 两种创作模式

### 5.1 中短篇 `short_medium`

中短篇面向一个核心冲突下的完整故事，工作区只呈现“蓝图”和“正文”两份可编辑文档。

| 项目 | 当前规则 |
| --- | --- |
| 目标字数 | 硬限制 6,000～80,000 字。 |
| 起始素材 | 必须提供灵感、开头、结尾、简略大纲或混合素材之一。 |
| 来源保存 | 原始起始素材完整保存为只读来源，不能被工作稿覆盖。 |
| 文档结构 | 一份蓝图、一份正文；正文复用单个 Chapter，不使用长篇多章导航。 |
| 保存 | 蓝图和正文均 1.2 秒延迟自动保存；自动保存不创建版本。 |
| 版本 | 人工提交、历史恢复和 Agent 候选都产生不可变版本及完整 Diff。 |
| AI 操作 | `generate_outline`、`generate_manuscript`、`replace_selection`、`full_check`。 |
| 生成策略 | 6,000～15,000 字可单次生成；更长正文按蓝图顺序串行分段，不能并行拼接。 |
| 采用规则 | 每次文档生成只产生一个候选，不自动采用，也不自动开始下一阶段。 |
| 视频 | 不开放；短篇视频深链会被服务端和前端收口到写作工作区。 |

中短篇的蓝图必须先形成已确认版本，才能作为正文生成的权威来源。工作稿存在未提交修改时，不能启动
依赖干净版本的 Agent 操作。选区修改按 Unicode 码点范围和 SHA-256 绑定来源，选区外内容必须逐字不变。

### 5.2 长篇连载 `long_serial`

长篇面向多章连续创作，提供章节、创作资料、结构化大纲、写作会话、多 Agent、审核、质量检查和视频入口。

| 项目 | 当前规则 |
| --- | --- |
| 规划建议 | 前端建议 30 万～100 万字、80～300 章、每章 3,000～6,000 字；这些是产品建议，不是 Core 硬上限。 |
| 项目初始化 | 自动创建第一章、空文本大纲、默认剧情进度和作品圣经。 |
| 正文结构 | 多章节，按 `order` 升序。 |
| AI 抽象 | 10 类 CreativeOperation，由 5 个核心 Agent 分工。 |
| 正式写入 | 手工编辑可按并发规则直接保存；Agent 变更必须先成为 ReviewArtifact。 |
| 质量门禁 | 章节完成前必须完成或跳过一致性终检。 |
| 视频 | 只对长篇显示，但当前属于仅开发环境能力。 |

## 7. 核心用户流程

### 7.1 长篇写作

~~~mermaid
flowchart TD
    A[注册或登录] --> B[创建长篇小说]
    B --> C[维护作品圣经、设定、大纲和参考资料]
    C --> D[编辑章节或发起 AI 会话]
    D --> E{手工还是 Agent 产物}
    E -->|手工| F[并发校验后保存正式内容]
    E -->|Agent| G[生成 ReviewArtifact]
    G --> H[自动复审或返工]
    H --> I[作者查看完整草案和 Diff]
    I -->|批准| J[Core 写入正式数据]
    I -->|修改或返工| H
    I -->|丢弃| K[保留历史任务，不写正式内容]
    F --> L[章节送审]
    J --> L
    L --> M[一致性终检]
    M --> N[标记章节完成]
~~~

### 7.2 中短篇

~~~mermaid
flowchart LR
    A[起始素材] --> B[蓝图工作稿]
    B --> C[蓝图版本]
    C --> D[正文工作稿]
    D --> E[正文版本]
    B --> F[AI 蓝图候选]
    C --> G[AI 正文候选]
    B --> H[AI 选区修改]
    D --> H
    D --> I[全文检查报告]
    F --> J[作者采用]
    G --> J
    H --> J
~~~

### 7.3 长篇章节影视化

~~~mermaid
flowchart LR
    A[章节快照] --> B[Scene/Beat/Shot 候选]
    B --> C[作者删改、合并、补镜并确认]
    C --> D[在正式镜头间分集]
    D --> E[视觉设定版本与逐镜参考]
    E --> F[逐镜即梦提示词]
    F --> G[关键帧]
    G --> H[Seedance 逐镜生成与选片]
    H --> I[非破坏性粗剪]
    I --> J[声音与字幕]
    J --> K[整集 MP4 导出]
~~~

这条影视化流程当前只代表开发环境实现，不代表生产可用。

## 8. 功能清单

### 8.1 官网、账号与会话

当前功能：

- 官网说明产品能力和作者最终确认原则；
- 用户名密码注册、登录、登出和读取当前用户；手机号全量开放时可配置关闭用户名新注册，旧账号登录保留；
- 已实现阿里云验证码 2.0、号码认证短信、Redis 挑战和手机号登录/自动建号接口，但两个生产开关默认关闭；
- 手机号首次核验成功时在同一事务创建独立账号、手机号身份和唯一注册奖励，已有手机号直接复用账号；
- 注册成功自动获得 1,000 积分并写入积分流水；
- 登录成功写入 HttpOnly Cookie，会话有效期 30 天；
- 生产 Cookie 使用 `Secure`、`SameSite=Lax`；
- 用户名统一转为小写，只允许 3～32 位小写字母、数字、下划线或短横线；
- 密码至少 6 个 UTF-16 code unit；兼容历史 bcrypt 前 72 个 UTF-8 字节语义；
- 登录按来源每分钟最多 20 次、同一来源和账号每分钟最多 5 次；
- 注册按来源及来源账号组合每小时最多 3 次；限流依赖 Redis，限流服务异常时认证失败关闭。

当前限制：

- `UserPhoneIdentity` 具名迁移已在服务器 `novelwriterdev` 完成备份、两次幂等执行和真实契约导出，尚未获准在正式库执行，生产手机号入口关闭；
- 老用户名账号不自动绑定手机号，不支持账号合并、手机号换绑或用手机号找回老账号；
- 没有邮箱、OAuth、微信或其他第三方登录；
- 没有忘记密码、修改密码、账号找回、注销账号和二次验证；
- 没有用户头像、昵称、资料页或设备会话管理；
- 没有管理员账号管理页面。

### 8.2 作品列表与小说项目

当前功能：

- 按更新时间倒序展示当前用户的小说；
- 展示名称、简介、章节数量、已应用文风和更新时间；
- 创建时选择中短篇或长篇模式；
- 长篇可填写目标字数、题材、主角、核心卖点、读者承诺和第一章目标；
- 中短篇必须填写目标字数、起始素材类型和完整起始素材；
- 新建长篇自动创建第一章、文本大纲、剧情进度和作品圣经；
- 修改小说简介时使用 `expectedUpdatedAt` 防止覆盖其他窗口更新；
- 工作区启动采用 bootstrap 聚合，后续按创作资料类别延迟加载。

当前限制：

- 没有小说删除、归档、恢复、复制、导入或整书导出；
- 没有通用小说重命名接口；
- 没有封面、标签、公开状态或发布渠道；
- 长篇创建接口没有幂等请求 ID，网络结果不确定时必须先查询确认，不能盲目重试；
- 项目只能属于一个用户，不能转让或共享。

### 8.3 长篇章节与编辑器

当前功能：

- 按顺序读取章节、新建下一章、切换章节；
- 默认章节标题为“第 N 章”；
- 使用 textarea 编辑标题和正文；
- 1.2 秒延迟自动保存；同一章节保存串行化，保存期间的新输入按最新快照继续；
- 保存和状态切换使用 `expectedUpdatedAt`；相同内容重试按幂等成功处理；
- 切章、新建章节、送审和进入视频前先强制 flush 当前草稿；
- 未落盘草稿按用户、小说、章节保存到浏览器本地存储，可在刷新后恢复；
- 字数统计统一排除 Unicode 空白和 `U+FEFF`，按 Unicode 码点计数；
- 展示当前章字数和全书总字数；
- 维护独立章节进展；
- 展示当前已批准 Beat Plan；
- 正文可选区，并把选区身份附加到 AI 协作面板；
- 章节状态为 `drafting`、`review`、`completed`，并可按门禁流转。

当前限制：

- 只有 `drafting` 章节可编辑，`review` 或 `completed` 必须先退回草稿；
- 没有章节删除、拖拽重排、批量移动、复制或跨书迁移；
- 没有富文本格式、批注、修订模式或多人实时协作；
- 没有真正离线模式，本地草稿只用于故障恢复；
- 没有整卷或多章一键连续生成入口。

### 8.4 章节送审和质量检查

当前功能：

- 章节送审后创建默认质量检查项；
- 当前可运行、跳过、重置和查询一致性终检；
- 终检查正文与设定冲突、角色 OOC、世界规则、伏笔误用和剧情逻辑；
- 运行绑定完整正文快照、SHA-256、章节更新时间和可选任务；
- 正文变化立即使旧报告或跳过状态失效；只修改标题不使正文检查失效；
- 只有最新运行且来源正文未变化时才能更新公共检查结果；
- 一致性终检完成或明确跳过后，章节才可标记完成；
- 报告保存五项一致性分数、问题、总评、质量门和返工说明。

当前限制：

- 公共 quality-check API 只支持 `consistency`；
- 商业性、技法和设定同步不是默认章后检查项，主要通过 Agent 审核流程完成；
- 质量任务依赖 Agent 和模型；运行中不能重复运行、跳过或重置；
- 系统没有批量章节终检页面。

### 8.5 创作资料库

#### 设定实体

当前可创建、读取、修改和删除：

- 角色：基础信息、外貌、性格、身份、背景、核心欲望、行为边界、说话习惯、关系原则、短期目标、
  实力、技能、状态和所属势力；
- 角色关系：10 种关系类型、亲密度 0～100、描述和起止时间；
- 角色经历：可绑定章节并排序；
- 物品：名称、类型、稀有度、效果、来源、描述和持有人；
- 地点：名称、类型、父地点、气候、文化和描述；
- 势力：名称、类型、根据地和描述；
- 术语：术语、定义和分类。

创建使用稳定 `clientRequestId`，更新和删除使用 `expectedUpdatedAt`。删除返回影响统计，不做隐藏级联。
跨小说关系、持有人、地点父子或势力引用会被拒绝。

#### 作品级资料

当前可维护：

- 故事背景；
- 世界设定；
- 作品圣经；
- 全书故事进展，最多 30,000 字符；
- 章节进展；
- 文本总纲；
- 剧情进度：当前阶段、目标、冲突、下个里程碑和进度百分比。

作品圣经记录篇幅模式、目标总字数、题材、目标读者、核心卖点、读者承诺、情绪收益、雷点、
对标方向和备注。

#### 结构化大纲

当前支持三层结构：

```text
stage 阶段/卷
  -> plot_unit 剧情单元
       -> chapter_group 章节组
```

节点支持状态、排序、预计/实际字数、章节范围和可选章节绑定。层级、父子关系和同级章节范围重叠由 Core 校验。

#### 伏笔

Core 和 Agent 草案链支持伏笔列表、创建、更新和删除。当前 Web 创作资料导航没有把伏笔作为独立手工主面板，
主要通过 Agent 草案和读取入口使用；CLI 目前只开放伏笔列表，没有伏笔写命令。

### 8.6 参考资料与 RAG

当前功能：

- 保存标题、类型、正文和可选来源 URL；
- 类型包括笔记、网页、书籍、图片描述和自定义；这里保存的是文本资料，不是通用二进制文件库；
- 创建、更新、删除和重新索引均有版本或内容哈希保护；
- RAG 索引是可重建派生数据，状态为 `disabled`、`ready` 或 `failed`；
- 单份资料最多形成 64 个向量块；公共向量查询 `topK` 为 1～20；
- RAG 结果只作为只读参考，不能直接写正式小说数据。

当前限制：

- 只有 Core 与 Agent 同时开启 `RAG_INDEX_ENABLED` 且 Embedding 配置完整时，语义索引才工作；
- 未配置时资料仍可保存，但 `ragStatus=disabled`；
- 当前索引来源只支持 `reference_material`，不是角色、章节、伏笔和文风的全库向量检索；
- 公共搜索接口接收 embedding 向量，不是面向普通用户的自然语言搜索页面；
- CLI 支持资料 CRUD 和重建索引，不提供向量搜索命令。

### 8.7 文风库

当前功能：

- 文风是用户级私有资产，不属于单本小说；
- 创建和删除文风；
- 上传多个严格 UTF-8 `.txt` 参考文件；
- 异步生成五个维度：创作方法、独特标识、生成风格、表达特征、风格特征；
- 可单独重新生成或手动修改一个维度；
- 可把自己的一个文风应用到自己的小说，也可清除应用；
- 画像任务、失败信息、原始字符数和使用字符数均可追踪。

当前限制：

- 单文件最大 50 MiB，只支持 `.txt`，必须为严格 UTF-8 且内容非空；
- 不支持 PDF、DOCX、EPUB、网页抓取或图片 OCR；
- 模型响应被截断、内容过滤或完成原因异常时任务失败，不保存半截画像；
- CLI 只支持把现有文风应用到小说或清除，不支持文风资产的创建、上传、画像、分节编辑和删除。

### 8.8 长篇 AI 会话与 Agent

`sync_lore` 已停止创建新任务，只保留历史快照解析兼容。

#### 会话和任务

当前功能：

- 写作会话的列表、创建、详情、重命名和删除；
- 用户、Agent 和系统消息持久化；
- 启动、查询、恢复和取消写作任务；
- SSE 流式展示 Operation 分类、Agent 状态、工具摘要、文本块、草案和终态；
- 按 `Last-Event-ID` 短期重放，断流后从 PostgreSQL 任务和草案状态恢复；
- 任务先写入 PostgreSQL 持久命令，再投递 Redis；短暂队列异常不丢已受理命令；
- 同一 `clientRequestId` 返回同一命令，不重复创建任务；
- 用户可以用 `@设定`、`@剧情`、`@写作`、`@校验`、`@编辑` 指定默认主责方向；
- 无法稳定识别的请求回退为普通问答；
- 正文和大纲支持来源绑定的选区改写，请求不把 `selectedText` 当作权威来源。

当前限制：

- 同一 `novelId` 同时只执行一个独立队列任务；不同小说最多并行 3 个任务；
- 所有普通 Agent、Reviewer、质量检查、中短篇和文风画像共享最多 3 个模型调用槽；
- 生产默认一个 Agent worker，`AGENT_MAX_CONCURRENCY` 只允许 1～3；
- 默认目标正文长度为 4,000 字，公共请求硬范围为 1～10,000,000；它只是目标，模型输出能力、计费额度和内容结构仍会限制实际结果；
- 当前不把供应商 `length` 结束原因当作自动续写信号；被截断响应直接失败；
- 没有多章无人值守连续生产、自动发布或“整本书一次生成”；
- Agent 聊天正文按普通文本渲染，不解析 Markdown；
- Agent 不连接 PostgreSQL，只能通过 Core 内部工具网关读取和提交业务事实。

### 8.9 ReviewArtifact、复审和正式应用

当前功能：

- Agent 对正文、设定、大纲、伏笔、Beat Plan 和视频镜头方案的正式变更先创建 ReviewArtifact；
- 草案保存 revision、evaluation、Diff、来源任务、来源版本和状态；
- Reviewer 可并行复审，合并为通过、返工、确定性 patch 或阻断；
- 完整返工生成新 revision，严格 patch 只修改可定位目标；
- 作者可以批准、带编辑批准、要求修改或丢弃；
- 结构化 `agent_updates` 支持只应用用户明确选择的 section 或 item；
- 选区草案只接受 replacement，Core 应用时再次校验来源版本、范围和哈希；
- 正式应用、草案状态和恢复命令在同一 Core 事务中处理；
- Redis 事件失败不能否定已经提交的 PostgreSQL 业务结果。

当前限制：

- Agent 草案不能自动成为正式内容；
- `revision_brief` 永远不能正式应用；
- patch 目标缺失、多重命中、重叠或版本冲突时不会静默升级为全文重写；
- 旧 `video_scene_plan` 只保留历史兼容，不得成为新的产品入口；
- SSE 事件只承担展示，审核成功与否以 Core 权威状态回读为准。

### 8.10 积分与模型计费

当前功能：

- 注册赠送 1,000 积分；
- 展示当前余额和近期积分流水；
- 模型调用前预授权余额，余额不足时不开始调用；
- 调用后按真实 prompt、cached 和 completion token 上报并扣费；
- 重复 usage 回调不重复扣费；
- 可按写作任务查询调用次数和 token 汇总；
- 可记录缓存未命中和 reasoning token 诊断字段；
- 失败场景可按明确规则写退款流水。

当前代码计价为：

- 非缓存输入：每 token 0.001 积分；
- 缓存输入：每 token 0.00002 积分；
- 输出：每 token 0.002 积分；
- 单次调用最小输出预算：128 token。

当前限制：

- 没有在线支付、微信/支付宝、银行卡、订阅套餐或自动续费；
- 充值页只提示联系管理员人工充值；
- 没有充值订单、发票、优惠券、套餐管理和面向用户的退款申请；
- 没有管理员充值后台；
- 视频真实供应商调用尚未获生产开放授权，不能把开发任务视为正式商业计费能力。

## 9. 长篇章节影视化详细功能

### 9.1 当前可用状态

影视化代码覆盖完整制作主链，但状态为“仅开发环境”：

- `VIDEO_PREVIEW_ENABLED` 默认关闭；
- Core 配置在 `production` 环境下主动拒绝开启视频预览、视频调度和 Seedance；
- 逐镜渲染 P0 与后期 P1-P3 结构只允许迁移到 `novelwriterdev`；
- 正式库已晋升部分章节改编域结构，但功能开关仍关闭；
- 当前没有经过授权的生产真实付费 Seedance 端到端验收。

历史读取可在开关关闭时保留，但所有新视频写入继续返回明确不可用错误。

### 9.2 视频项目与素材

当前功能：

- 为长篇小说创建视频项目；模式为 concept、trailer、highlight 或 series；
- 当前章节影视化 Web 默认创建 series、9:16、中文项目；
- 画幅支持 16:9、4:3、1:1、3:4、9:16、21:9 和 adaptive；
- 上传图片、视频和音频，并按魔数识别真实格式；
- 支持 JPEG、PNG、WebP、MP4/MOV、WAV 和 MP3；
- 图片最大 30 MiB、视频最大 200 MiB、音频最大 100 MiB；
- 音视频必须由 ffprobe 读取真实时长，不能信任客户端声明；
- 素材职责包括身份、服装、场景、道具、风格、故事板、关键帧、运动、摄影机、声音、环境、音效和音乐；
- 用户必须声明权利状态；只有 `confirmed` 且锁定的素材可以进入正式视觉、关键帧、音轨或供应商请求；
- 素材文件只通过受控 storage key 访问，不接受客户端服务器路径。

当前限制：

- 当前章节影视化主链只接受 `series` 项目；concept、trailer 和 highlight 仍可作为项目枚举创建，
  但旧 VideoScene 流程已退役，没有与 series 等价的完整新制作流程；
- 普通上传不能冒充 `episode_export`，成片只能由导出任务创建；
- 视频项目创建和素材上传当前没有幂等请求 ID，网络结果不确定时必须先回读核对；
- 没有素材文件删除、标签搜索、文件夹或云对象存储 UI；
- 没有自动版权识别，权利确认是作者声明和产品门禁。

### 9.3 章节快照与电影化拆镜

当前功能：

- 只允许 `long_serial`；
- 从完整章节和 `expectedChapterUpdatedAt` 创建不可变改编快照；
- 空正文不能改编；单章超过 120,000 字时拒绝；
- AI 第一阶段识别 Scene、DramaticBeat 和观众覆盖目标，第二阶段设计 Shot；
- 不按对白、句号、段落或固定秒数机械切镜；
- 每个镜头保存目的、景别、机位、运镜、可见动作、表演、声音、对白位置、来源范围、观众获得、
  目标绑定、时长和切镜理由；
- 节奏预设为短剧叙事、电影叙事、对白驱动；单集目标为 60、90 或 120 秒；
- 候选经过连续性 Reviewer，最多一次完整返工；第二轮仍有问题时作为非阻断 findings 交给作者；
- 工作台显示 Scene → Beat → Shot 时间线、目标覆盖、来源覆盖、总时长和平均镜头时长；
- 作者可编辑镜头字段和目标绑定；从原文选区重绑来源或新增动作镜头；新增视听补充镜头；
- 作者可删除镜头、恢复最近删除、合并同一 Beat 相邻镜头、合并相邻 Scene；
- 每个 Beat 至少保留一个镜头；合并后单镜不超过 15 秒且对白位置不能冲突；
- 作者确认完整候选后才创建不可变正式镜头方案；旧正式版本保留；
- 可基于当前正式版本和最多 1,200 字修订重点生成新候选。

硬门禁只负责来源、版本、时间线、Key、父子关系、字段完整性和单镜可执行性。平均时长、慢镜比例、
空镜数量、景别单调和相邻重复属于提示，不得阻止作者确认。

### 9.4 分集

当前功能：

- 只在正式镜头之间设置集尾；
- 优先提示在戏剧节拍结束处断集；
- 显示每集镜头构成、时长和超出目标时长提醒；
- 每次保存创建独立不可变 `VideoEpisodePlanVersion`；
- 一份镜头方案最多接受 119 个断点，当前提示词批量目标最多 120 镜。

当前限制：

- 分集不会自动修改或重排镜头；
- 没有跨章节合并为一集的产品流程；当前改编根固定到单章快照。

### 9.5 角色、服装、场景和道具稳定

当前功能：

- 从角色、地点和物品设定建立视觉设定槽；
- 职责为角色身份、角色服装、场景和道具；
- 上传图片先成为候选，不改变当前正式版本；
- 作者确认权利并批准后创建不可变视觉版本；旧版本保留；
- 每个槽可维护变体 key、名称、保留特征、排除特征和默认强度；
- 单个包含/排除列表最多 20 项，每项最多 120 字；
- 每镜最多绑定 20 个不重复的正式视觉版本，强度为 1～100；
- 提示词候选和正式版本冻结精确视觉版本、素材哈希和强度；后来换图不会修改旧提示词依据；
- 有图片参考时，文字只保留本镜必要身份锚点、动作、状态和可见变化，减少重复静态设定。

当前限制：

- 系统不生成角色图、场景图或道具图，只管理外部生成或用户上传的图片；
- 图片不会自动获得批准，AI 不能代替作者确认权利或定妆；
- 当前没有人脸训练、LoRA、角色模型训练或跨项目视觉资产复用产品流程。

### 9.6 逐镜即梦提示词

当前功能：

- 只针对当前正式镜头方案生成；可批量生成未完成镜头或单镜生成；
- 每个目标镜头只接收自己的 Scene、Beat、Shot、来源范围和相关冻结设定，不接收整章或邻镜完整事件；
- 结构包含主体、动作、表情与视线、摄影、声音和负面约束；
- 正式景别为大全景、全景、中景、近景、特写，并与模型中文标签严格一致；
- 结构或编译首次失败时最多纠正一次；再次硬失败时任务失败，不保存半截结果；
- 语义质量问题以最多 12 条 warning 进入可编辑候选；
- 作者可查看结构化依据、手动编辑完整提示词并保存正式版本；
- 正式提示词最大 2,000 字；AI 编译文本按镜头时长分别限制为 360、480 或 640 字，超限不静默截断；
- PromptHead 使用 revision CAS；旧 PromptVersion 和视觉快照保持不变。

当前限制：

- 当前只面向即梦/Seedance 编译，不是多供应商提示词市场；
- 提示词生成不会直接创建视频任务；必须由作者保存正式提示词后另行生成；
- 高成本特效缺少镜头、来源、设定或参考依据时只给 warning，不会自动编造或删除内容。

### 9.7 关键帧

当前功能：

- 每镜有首态 `initial_state`、过渡锚点 `transition_anchor`、末态 `end_state` 三个角色；
- 可上传图片并采用，也可从已有 Take 指定毫秒时间点抽帧；
- 每个角色维护不可变版本和当前 head，切换时使用 revision CAS；
- 连续性检查可把前镜末态与后镜首态问题显示为 info、warning 或 blocking；
- 新渲染任务按首态、过渡、末态顺序冻结当前关键帧。

当前限制：

- 抽帧依赖 FFmpeg/ffprobe；缺少工具时历史读取仍可用，但抽帧被阻断；
- Seedance 接口只接受有序参考图，没有可依赖的独立首帧/尾帧参数；Core 通过顺序和文本说明表达角色；
- 没有图片生成模型自动补帧。

### 9.8 逐镜生成与选片

当前功能：

- 只从镜头当前正式 PromptHead 创建显式任务；
- 每次任务冻结镜头方案、提示词版本、视觉参考、关键帧、画幅、时长和供应商参数；
- 供应商当前固定为 Seedance，模型默认 `doubao-seedance-2-5-260628`；
- 时长 2～12 秒，分辨率 480p、720p 或 1080p，可选择生成音频和水印；
- 任务状态覆盖等待、提交、提交结果未知、供应商排队/运行、归档、成功、失败、过期和取消；
- 供应商临时 URL 不作为播放事实，只有 Core 完整归档后才创建不可变 Take；
- 可按原冻结清单显式重试；不会自动使用后来修改的提示词或参考图；
- 作者最多并排比较两个 Take，并通过 CAS 确认当前采用 Take；旧 Take 和决定命令保留。

当前限制：

- 真实调用默认关闭，生产环境禁止开启；
- `submission_unknown` 不自动重提，避免重复计费；作者新建任务可能再次计费；
- 当前没有公共取消供应商任务的作者操作；
- 每个成功任务最多产生一个 Take；
- 没有一键整章付费生成，产品按镜头显式提交。

### 9.9 非破坏性粗剪

当前功能：

- 以正式分集为边界生成默认时间线；
- 按正式镜头顺序放入已选 Take，缺少 Take 的镜头显示等长占位；
- 可为每镜选择 Take、设置源入点、源出点、输出时长和转场；
- 当前转场只支持硬切 `cut` 和淡黑 `fade_black`；
- 每次保存创建不可变编辑版本，支持从任一历史版本加载并创建分支；
- EditHead 使用 revision CAS，不覆盖另一个页面刚保存的版本；
- 单片段输出时长 0.5～120 秒，转场最长 2 秒；单版本最多 500 个片段；
- 素材时长未知时只能使用完整素材，不能静默裁切。

当前限制：

- 这是镜头级基础粗剪，不是 Premiere、剪映或 DaVinci 级非线性编辑器；
- 没有关键帧动画、变速、画中画、调色、滤镜、遮罩和复杂转场；
- 有占位镜头的粗剪不能导出正式成片。

### 9.10 声音、字幕和整集输出

当前功能：

- 音轨类型为对白、旁白、环境、音效和音乐；
- 上传 WAV 或 MP3 后，经权利确认和真实时长探测才能进入时间线；
- 设置时间线位置、源入出点、增益 -60～+12 dB、最长 10 秒淡入淡出；
- Seedance Take 原声作为底声保留，附加音轨在其上混合；
- 从正式镜头 `speechMode/spokenText` 生成可编辑字幕建议；
- 字幕支持时间、可选说话人和最多 2,000 字文本；
- 单声音版本最多 1,000 个音频片段和 2,000 条字幕；
- 声音版本固定引用一个粗剪版本；粗剪变化时显示旧声音版本已过期，不静默套用；
- 导出冻结粗剪、声音、字幕、素材哈希和参数；
- 导出 720p 或 1080p MP4，帧率 24、25 或 30，可选择烧录字幕；
- 失败重试创建新任务并精确复用旧清单，不覆盖旧成片。

当前限制：

- 没有 TTS、声音克隆、自动配音、自动作曲或自动音效生成；
- 没有自动响度标准化、降噪、母带和高级混音 UI；
- 导出依赖 FFmpeg 和 ffprobe，单进程耐久导出领取并发固定为 1；
- 没有成片发布、平台分发、审核报备、数据分析或商业授权管理；
- P4 局部 Retake 和视频内编辑尚未实现。

## 10. CLI 与自动化能力

CLI 当前注册 125 个具体命令：

| 命令域 | 数量 | 覆盖 |
| --- | ---: | --- |
| `auth.*` | 3 | 登录、登出、当前身份。 |
| `short.*` | 13 | 中短篇创建、拉取、工作稿、版本和 Agent。 |
| `long.novel.*` / `long.chapter.*` | 10 | 长篇小说和章节读写。 |
| 长篇资料多前缀 | 41 | 规划、设定、大纲节点、关系、经历、参考资料和文风应用。 |
| 长篇任务审核多前缀 | 17 | 会话、任务、Agent、草案和质量检查。 |
| `long.video.*` | 41 | 视频项目至整集导出的当前主链。 |

CLI 的产品规则：

- `auth.login` 是唯一交互命令；其他命令从 stdin 读取 UTF-8 JSON；
- 普通命令输出 JSON，watcher 输出 JSONL；完整正文和结构不得截断；
- 二进制下载必须指定输出文件，不把媒体字节写入 stdout；
- 只访问 `/api/v1/**`，不连接数据库、Agent Service 或内部接口；
- 远程地址必须使用 HTTPS，本地 HTTP 只允许回环地址；
- CLI 不绕过归属、Diff 确认、ReviewArtifact、CAS、素材权利或视频开关；
- 停止 watcher 只停止本地观察，不取消服务端任务。

CLI 当前不是 148 个公共 API 的逐接口镜像，明确缺口包括：

- 不提供注册命令；
- 不提供积分余额、用量和任务 token 查询命令；
- 不提供工作流调试命令；
- 不提供文风资产创建、TXT 上传、画像生成、分节编辑和删除命令；
- 不提供 RAG embedding 搜索命令；
- 伏笔只有列表，没有手工写命令；
- 健康检查和 OpenAPI 文档不包装为业务命令。

当前生产 CLI 凭据后端只允许 Windows Credential Manager 的 `WinVaultKeyring`，不会回退到明文文件。
因此 macOS/Linux 不能直接作为当前生产 CLI 的受支持凭据平台；这也是 Java CLI 重写必须明确解决的产品选择。

完整 125 命令及字段见 `tools/inkforge-cli/README.md`，注册表是命令存在性的权威。

## 12. 内部支撑与运维能力

### 12.1 Core 与 Agent 边界

- 浏览器只访问 `/api/v1/**`；
- 30 个 Core 内部操作覆盖质量回调、RAG 回调、文风画像回调、模型授权和计费、Agent 工具网关、
  写作事件/检查点/终态、草案复审和视频回调；
- 内部请求同时校验直连网段、Ed25519 服务身份、请求体绑定、短有效期和重放保护；
- Agent Service 不接收 `DATABASE_URL`，不加入数据网络，不直接写小说数据；
- Nginx 对公网阻断 `/internal/**`。

### 12.2 耐久任务和恢复

- 写作命令、质量运行、文风画像、RAG 索引、视频改编、渲染和导出都以 PostgreSQL 为长期事实；
- Redis 承载队列、短期事件、租约、限流和重放保护，不是最终业务状态；
- 后台 dispatcher/reconciler 按到期行补投或对账，Core/Agent 重启后可继续；
- 完成、失败或取消的 Agent 队列 tombstone 默认在 Redis 保留 7 天，至少 1 天；
- Redis 内存上限为 64 MiB，策略为 `noeviction`；满时明确拒绝新写入，不能淘汰业务队列或防重放键；
- 后台任务失败会退避重启，并反映在 readiness，而不是伪装健康。

### 12.3 日志与调试

- 人工工作流日志记录完整模型输入输出和规范化元数据，不记录服务令牌、计费 grant 或 DeepSeek
  `reasoning_content`；
- 大日志按帧保存，不静默截断；残缺尾部需隔离后恢复；
- 工作流调试读取默认关闭；开启后仍校验登录、作品归属和服务权限；
- LangGraph Studio 只用于开发调试，不是作者正式工作区。

### 12.4 部署与数据

- 生产由宿主机 Nginx、Compose Nginx、Web、Core、Agent 和 Redis 组成；PostgreSQL 14 运行在宿主机；
- 只有 Nginx 对外发布端口，Agent 不发布宿主机端口；
- 2 核 2 GB 是当前默认部署预算，每个 Python 服务一个 worker；
- 发布在 Runner 预构建镜像，服务器不现场构建；
- 发布失败时按经验证的上一标签恢复 Web、Core 和 Agent，回滚成功仍表示本次发布失败；
- 应用启动不自动建表、删表或迁移；schema guard 只读核对结构；
- 只有用户明确批准的具名迁移可以在备份、隔离验证和门禁下执行。

## 13. 横向产品不变量

这些规则不是实现细节，Java Core 重写后也必须保持：

1. **作者拥有最终正式写入权。** Agent 对正文、设定、大纲、伏笔、Beat Plan 和视频方案的正式变更
   必须经过持久草案和作者确认。
2. **不同数据层不能混写。** 正文、章节进展、故事进展、设定、大纲、伏笔、Beat Plan、视频方案和
   后期决定各自独立。
3. **来源必须可重建。** 选区、章节改编、提示词、渲染和导出都冻结来源版本、哈希或不可变清单。
4. **不静默截断。** 正文、草案、Diff、模型输出、工具结果、日志和持久数据不能为了通过限制而截断；
   超限必须失败、分段或要求用户处理。
5. **写操作必须防重复。** 能提供 `clientRequestId` 的入口按稳定指纹幂等；不能提供的入口在网络结果
   不确定时先回读核对，不能盲目重试。
6. **并发冲突必须显式。** 正文、资料、草案、镜头方案、视觉参考、提示词、Take 和后期 head 使用
   时间戳或 revision CAS，旧页面不能覆盖新版本。
7. **异步受理不等于完成。** 前端和 CLI 必须回读任务、草案或 outcome；SSE/JSONL 只辅助观察。
8. **历史版本不可变。** 恢复或修改创建新版本，不能重写旧版本事实。
9. **软质量建议不替代作者。** 节奏、景别、空镜、平均时长和视觉风格等建议不能无证据地变成硬阻断。
10. **服务边界不可绕过。** Agent 无数据库权限，浏览器和 CLI 无内部接口权限，正式媒体必须经过素材
    权利和受控存储。

## 14. 当前主要限制与非目标

### 14.1 商业化

- 手机号认证已完成服务器开发库迁移、协议正文、公开联系渠道和真实短信送达测试；正式库迁移与生产开放已获
  批准但在受控执行完成前仍不可视为线上开放；无邮箱体系；
- 无账号找回、改密、注销、风控后台和客服工单；
- 无在线支付、订单、订阅、套餐、优惠、发票和用户退款申请；
- 无管理员运营后台；
- 无内容商业化、版权交易或收益分成。

### 14.2 协作与内容管理

- 单用户所有权，没有团队、分享、评论、审稿角色或多人实时编辑；
- 无小说删除、归档、复制、导入、整书导出和发布；
- 无章节删除、重排、批量操作和跨书移动；
- 无富文本、批注、修订模式和离线编辑；
- 无移动端专用体验。

### 14.3 AI 写作

- 不能无人值守连续生产整本书；
- 章后质量检查只有一致性；
- RAG 只覆盖参考资料，且依赖可选 Embedding 配置；
- 文风只从 TXT 生成；
- 模型被截断时不自动续写；
- 当前模型供应商和额度会直接影响可用性、时延和成本。

### 14.4 视频

- 生产功能关闭，P0-P3 数据结构只获开发库授权；
- 当前只接 Seedance；
- 无图片生成、TTS、声音克隆和音乐生成；
- 无公共取消渲染、整章一键生成和跨章节成集；
- 粗剪只支持基础入出点与两种转场；
- 无 P4 局部 Retake、高级视频编辑、调色、特效和发布分发；
- 真实付费端到端调用尚未作为生产能力验收。

### 14.5 自动化与平台

- CLI 不是公共 API 全量镜像；
- 当前生产 CLI 凭据仅支持 Windows Credential Manager；
- 生产是单机 2 核 2 GB 预算，不是多地域、高可用或水平扩展架构；
- PostgreSQL schema 默认冻结，应用不能自动迁移；
- 当前没有公开 Webhook、第三方插件市场或外部开发者 API 产品。

## 15. Java Core 重写的产品验收基线

Java 重写的第一目标是行为等价，不是顺便增加功能。完成迁移至少要证明：

- 两种创作模式、原等价基线 148 个公共操作和 Agent 所需 30 个 Core 内部操作保持契约语义；后续新增的
  2 个手机号认证操作不得改变原接口行为；
- 125 个 CLI 命令在迁移方案确定的 Java CLI 中保持或经明确产品决策替代；
- 登录 Cookie、资源归属、积分预授权与扣费结果一致；
- 章节自动保存、状态门禁、质量失效规则和完整字数统计一致；
- CreativeOperation、ReviewArtifact、部分应用、选区来源绑定、SSE 恢复和任务对账一致；
- 视频在生产继续关闭，不能因迁移意外启用；开发环境的拆镜、视觉、提示词、Take 和后期版本语义一致；
- schema 指纹守卫、无自动 DDL、受控文件存储和服务身份边界一致；
- Python Core 回滚镜像退役前，Java 对当前功能和限制的 TDD/差异测试全部通过。

手机号登录已在 Core 完整切换后通过 `docs/specs/2026-08-27-aliyun-phone-auth.md` 独立实施，仍受迁移和
生产开关门禁；在线支付和其他商业功能继续要求另立规格。
