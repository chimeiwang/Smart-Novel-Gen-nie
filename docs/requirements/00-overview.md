## 2. 产品结论

InkForge 当前是一套面向中文小说作者的桌面优先创作工作台，核心不是“让 AI 自动写完整本书”，而是把
作品资料、写作过程、AI 草案、作者审核和版本追踪放进同一条受控链路。

当前产品已经形成三条主要能力线：

- 中短篇：起始素材 → 蓝图 → 正文 → 不可变版本 → AI 候选或全文检查；
- 长篇连载：项目与章节 → 设定和大纲 → AI 会话与多 Agent → 草案审核 → 章节终检；
- 长篇剧集制作：独立 Episode 与多章来源 → 单集剧本 → 稳定分镜 → 影响复核与制作基线 → 视觉／关键帧 → 逐镜生成 → 后期交付。

其中前两条属于正常产品实现；Episode 视频 P0～P4 的仓内部分已在当前代码、开发结构、唯一 Web／公共 API／普通 CLI 中落地，
并以受控模拟 MP4 验证媒体主链。生产配置仍禁止视频写入、后台调度和真实 Seedance 调用，因此不能把它描述为已在线上开放的商业能力。

从成熟度看，InkForge 已经具备较完整的创作领域和耐久任务基础，但还不是成熟商业 SaaS：手机号认证代码、
服务器开发库与正式库迁移、公开联系渠道、真实短信送达测试和生产开放已完成，真实浏览器完整登录仍待用户验收，
账号找回、在线支付、管理员后台、多人协作、移动端和内容发布分发仍未完成。

- 管理员后台角色；

## 5. 两种创作模式

### 5.1 中短篇 `short_medium`

中短篇面向一个核心冲突下的完整故事，工作区只呈现“蓝图”和“正文”两份可编辑文档。

| 项目 | 当前规则 |
| --- | --- |
| 目标字数 | 硬限制 6,000～80,000 字。 |
| 起始素材 | 必须提供灵感、开头、结尾、简略大纲或混合素材之一。 |
| 来源保存 | 原始起始素材完整保存为只读来源，不能被工作稿覆盖。 |
| 文档结构 | 一份蓝图、一份正文；正文复用单个 Chapter，不使用长篇多章导航。 |
| 保存 | 蓝图和正文均 1.2 秒延迟自动保存；自动保存不创建版本。 |
| 版本 | 人工提交、历史恢复和 Agent 候选都产生不可变版本及完整 Diff。 |
| AI 操作 | `generate_outline`、`generate_manuscript`、`replace_selection`、`full_check`。 |
| 生成策略 | 6,000～15,000 字可单次生成；更长正文按蓝图顺序串行分段，不能并行拼接。 |
| 采用规则 | 每次文档生成只产生一个候选，不自动采用，也不自动开始下一阶段。 |
| 视频 | 不开放；短篇视频深链会被服务端和前端收口到写作工作区。 |

中短篇的蓝图必须先形成已确认版本，才能作为正文生成的权威来源。工作稿存在未提交修改时，不能启动
依赖干净版本的 Agent 操作。选区修改按 Unicode 码点范围和 SHA-256 绑定来源，选区外内容必须逐字不变。

四项 V2 已完成仓内接线和本地独立 Java Core/Python Agent、受控 Fake Provider 验收。正文每段由独立耐久
Step 执行并保留完整前缀；生成 Run 完成只产生待采用版本，仍须原预览/确认/采用流程；全文检查只返回完整
报告。该结果不代表真实供应商或生产已验收，详见 `docs/specs/2026-09-05-durable-short-medium-workflows.md`。

### 5.2 长篇连载 `long_serial`

长篇面向多章连续创作，提供章节、创作资料、结构化大纲、写作会话、多 Agent、审核、质量检查和视频入口。

| 项目 | 当前规则 |
| --- | --- |
| 规划建议 | 前端建议 30 万～100 万字、80～300 章、每章 3,000～6,000 字；这些是产品建议，不是 Core 硬上限。 |
| 项目初始化 | 自动创建第一章、空文本大纲、默认剧情进度和作品圣经。 |
| 正文结构 | 多章节，按 `order` 升序。 |
| AI 抽象 | 10 类 CreativeOperation，由 5 个核心 Agent 分工。 |
| 正式写入 | 手工编辑可按并发规则直接保存；Agent 变更必须先成为 ReviewArtifact。 |
| 质量门禁 | 章节完成前必须完成或跳过一致性终检。 |
| 视频 | 只对长篇显示，但当前属于仅开发环境能力。 |

~~~mermaid
    J --> L
    L --> M[一致性终检]
~~~

~~~mermaid
flowchart LR
~~~

## 8. 功能清单

### 8.1 官网、账号与会话

当前功能：

- 官网说明产品能力和作者最终确认原则；
- 用户名密码注册、登录、登出和读取当前用户；手机号全量开放时可配置关闭用户名新注册，旧账号登录保留；
- 已实现阿里云验证码 2.0、号码认证短信、Redis 挑战和手机号登录/自动建号接口，但两个生产开关默认关闭；
- 手机号首次核验成功时在同一事务创建独立账号、手机号身份和唯一注册奖励，已有手机号直接复用账号；
- 注册成功自动获得 1,000 积分并写入积分流水；
- 登录成功写入 HttpOnly Cookie，会话有效期 30 天；
- 生产 Cookie 使用 `Secure`、`SameSite=Lax`；
- 用户名统一转为小写，只允许 3～32 位小写字母、数字、下划线或短横线；
- 密码至少 6 个 UTF-16 code unit；兼容历史 bcrypt 前 72 个 UTF-8 字节语义；
- 登录按来源每分钟最多 20 次、同一来源和账号每分钟最多 5 次；
- 注册按来源及来源账号组合每小时最多 3 次；限流依赖 Redis，限流服务异常时认证失败关闭。

当前限制：

- `UserPhoneIdentity` 具名迁移已在服务器 `novelwriterdev` 完成备份、两次幂等执行和真实契约导出，尚未获准在正式库执行，生产手机号入口关闭；
- 老用户名账号不自动绑定手机号，不支持账号合并、手机号换绑或用手机号找回老账号；
- 没有邮箱、OAuth、微信或其他第三方登录；
- 没有忘记密码、修改密码、账号找回、注销账号和二次验证；
- 没有用户头像、昵称、资料页或设备会话管理；
- 没有管理员账号管理页面。

### 8.2 作品列表与小说项目

当前功能：

- 按更新时间倒序展示当前用户的小说；
- 展示名称、简介、章节数量、已应用文风和更新时间；
- 创建时选择中短篇或长篇模式；
- 长篇可填写目标字数、题材、主角、核心卖点、读者承诺和第一章目标；
- 中短篇必须填写目标字数、起始素材类型和完整起始素材；
- 新建长篇自动创建第一章、文本大纲、剧情进度和作品圣经；
- 修改小说简介时使用 `expectedUpdatedAt` 防止覆盖其他窗口更新；
- 工作区启动采用 bootstrap 聚合，后续按创作资料类别延迟加载。

当前限制：

- 没有小说删除、归档、恢复、复制、导入或整书导出；
- 没有通用小说重命名接口；
- 没有封面、标签、公开状态或发布渠道；
- 长篇创建接口没有幂等请求 ID，网络结果不确定时必须先查询确认，不能盲目重试；
- 项目只能属于一个用户，不能转让或共享。

### 8.3 长篇章节与编辑器

当前功能：

- 按顺序读取章节、新建下一章、切换章节；
- 默认章节标题为“第 N 章”；
- 使用 textarea 编辑标题和正文；
- 1.2 秒延迟自动保存；同一章节保存串行化，保存期间的新输入按最新快照继续；
- 保存和状态切换使用 `expectedUpdatedAt`；相同内容重试按幂等成功处理；
- 切章、新建章节、送审和进入视频前先强制 flush 当前草稿；
- 未落盘草稿按用户、小说、章节保存到浏览器本地存储，可在刷新后恢复；
- 字数统计统一排除 Unicode 空白和 `U+FEFF`，按 Unicode 码点计数；
- 展示当前章字数和全书总字数；
- 维护独立章节进展；
- 展示当前已批准 Beat Plan；
- 正文可选区，并把选区身份附加到 AI 协作面板；
- 章节状态为 `drafting`、`review`、`completed`，并可按门禁流转。

当前限制：

- 只有 `drafting` 章节可编辑，`review` 或 `completed` 必须先退回草稿；
- 没有章节删除、拖拽重排、批量移动、复制或跨书迁移；
- 没有富文本格式、批注、修订模式或多人实时协作；
- 没有真正离线模式，本地草稿只用于故障恢复；
- 没有整卷或多章一键连续生成入口。

### 8.4 章节送审和质量检查

当前功能：

- 章节送审后创建默认质量检查项；
- 当前可运行、跳过、重置和查询一致性终检；
- 终检查正文与设定冲突、角色 OOC、世界规则、伏笔误用和剧情逻辑；
- 运行绑定完整正文快照、SHA-256、章节更新时间和可选任务；
- 正文变化立即使旧报告或跳过状态失效；只修改标题不使正文检查失效；
- 只有最新运行且来源正文未变化时才能更新公共检查结果；
- 一致性终检完成或明确跳过后，章节才可标记完成；
- 报告保存五项一致性分数、问题、总评、质量门和返工说明。

当前限制：

- 公共 quality-check API 只支持 `consistency`；
- 商业性、技法和设定同步不是默认章后检查项，主要通过 Agent 审核流程完成；
- 质量任务依赖 Agent 和模型；运行中不能重复运行、跳过或重置；
- 系统没有批量章节终检页面。

### 8.5 创作资料库

#### 设定实体

当前可创建、读取、修改和删除：

- 角色：基础信息、外貌、性格、身份、背景、核心欲望、行为边界、说话习惯、关系原则、短期目标、
  实力、技能、状态和所属势力；
- 角色关系：10 种关系类型、亲密度 0～100、描述和起止时间；
- 角色经历：可绑定章节并排序；
- 物品：名称、类型、稀有度、效果、来源、描述和持有人；
- 地点：名称、类型、父地点、气候、文化和描述；
- 势力：名称、类型、根据地和描述；
- 术语：术语、定义和分类。

创建使用稳定 `clientRequestId`，更新和删除使用 `expectedUpdatedAt`。删除返回影响统计，不做隐藏级联。
跨小说关系、持有人、地点父子或势力引用会被拒绝。

#### 作品级资料

当前可维护：

- 故事背景；
- 世界设定；
- 作品圣经；
- 全书故事进展，最多 30,000 字符；
- 章节进展；
- 文本总纲；
- 剧情进度：当前阶段、目标、冲突、下个里程碑和进度百分比。

作品圣经记录篇幅模式、目标总字数、题材、目标读者、核心卖点、读者承诺、情绪收益、雷点、
对标方向和备注。

#### 结构化大纲

当前支持三层结构：

```text
stage 阶段/卷
  -> plot_unit 剧情单元
       -> chapter_group 章节组
```

节点支持状态、排序、预计/实际字数、章节范围和可选章节绑定。层级、父子关系和同级章节范围重叠由 Core 校验。

#### 伏笔

Core 和 Agent 草案链支持伏笔列表、创建、更新和删除。当前 Web 创作资料导航没有把伏笔作为独立手工主面板，
主要通过 Agent 草案和读取入口使用；CLI 目前只开放伏笔列表，没有伏笔写命令。

### 8.6 参考资料与 RAG

当前功能：

- 保存标题、类型、正文和可选来源 URL；
- 类型包括笔记、网页、书籍、图片描述和自定义；这里保存的是文本资料，不是通用二进制文件库；
- 创建、更新、删除和重新索引均有版本或内容哈希保护；
- RAG 索引是可重建派生数据，状态为 `disabled`、`ready` 或 `failed`；
- 单份资料最多形成 64 个向量块；公共向量查询 `topK` 为 1～20；
- RAG 结果只作为只读参考，不能直接写正式小说数据。

当前限制：

- 只有 Core 与 Agent 同时开启 `RAG_INDEX_ENABLED` 且 Embedding 配置完整时，语义索引才工作；
- 未配置时资料仍可保存，但 `ragStatus=disabled`；
- 当前索引来源只支持 `reference_material`，不是角色、章节、伏笔和文风的全库向量检索；
- 公共搜索接口接收 embedding 向量，不是面向普通用户的自然语言搜索页面；
- CLI 支持资料 CRUD 和重建索引，不提供向量搜索命令。

### 8.7 文风库

当前功能：

- 文风是用户级私有资产，不属于单本小说；
- 创建和删除文风；
- 上传多个严格 UTF-8 `.txt` 参考文件；
- 异步生成五个维度：创作方法、独特标识、生成风格、表达特征、风格特征；
- 可单独重新生成或手动修改一个维度；
- 可把自己的一个文风应用到自己的小说，也可清除应用；
- 画像任务、失败信息、原始字符数和使用字符数均可追踪。

当前限制：

- 单文件最大 50 MiB，只支持 `.txt`，必须为严格 UTF-8 且内容非空；
- 不支持 PDF、DOCX、EPUB、网页抓取或图片 OCR；
- 模型响应被截断、内容过滤或完成原因异常时任务失败，不保存半截画像；
- CLI 只支持把现有文风应用到小说或清除，不支持文风资产的创建、上传、画像、分节编辑和删除。

当前源码的 V2 文风画像使用用户级 Run（`novelId=null`），受理时冻结完整参考文件。整套五节串行、单节重做
只处理目标节，模型只返回纯文本；Core 沿原业务直接物化 WritingStyle，整套最后一次性写入，不增加草案采用。
历史 V1 StylePortraitTask 与恢复路径保留，新 V2 不建旧任务影子行，原任务查询双读。参考增删与人工编辑不新增
限制。Agent/Core、全仓门禁及隔离独立进程验证均通过，结果见
`docs/specs/2026-09-05-durable-style-portrait.md` 最终记录为准，不代表生产、固定 CLI 或活动 Skills 已更新。

### 8.8 长篇 AI 会话与 Agent

当前仓内 Durable Agent V2 Catalog 共 23 项：19 项覆盖既有长篇／中短篇／质量／文风／RAG 能力，4 项覆盖
Episode 剧本起草／修订与分镜起草／限定范围修订。旧章节视频定义已从 Catalog、公共／内部路由和后台运行入口删除。
Episode 视频 Run 冻结完整来源和 revision，完成只物化候选，仍须作者采用
到工作稿并另行确认正式版本；分镜限定范围修订由 Core 合并保留未选镜头，模型不能全量覆盖。

这些数字表示当前仓内契约与开发实现，不代表真实供应商或生产开放。新 Episode 视频操作继续受视频门禁、
同小说互斥、预算、取消、幂等和完整 Evidence 约束；旧章节视频工作流不能再创建或调度。
长篇结构化五项的具体证据见 `docs/specs/2026-09-05-durable-structured-agent-updates.md`。

一致性终检保留原质量检查与 CLI 命令，完整报告、失败和取消由 Core 投影；一次格式纠正为独立耐久 Step，
不增加质量阈值或作者操作限制。具体验收见 `docs/specs/2026-09-05-durable-consistency-quality.md`。

自然新请求使用 resolver v3，冻结十项无选区操作及默认 scope：设定两项/大纲两项为 novel，伏笔和原章节五项
为当前 chapter；节点等不匹配范围须澄清或走显式入口，不让模型猜 ID。历史 resolver v1/v2、selection v1
和原三项/五项授权保持不变。公共请求始终保留 chapter 锚点，不新增聚合 target。

#### 会话和任务

当前功能：

- 写作会话的列表、创建、详情、重命名和删除；
- 用户、Agent 和系统消息持久化；
- 启动、查询、恢复和取消写作任务；
- SSE 流式展示 Operation 分类、Agent 状态、工具摘要、文本块、草案和终态；
- 按 `Last-Event-ID` 短期重放，断流后从 PostgreSQL 任务和草案状态恢复；
- V1 任务先写入 PostgreSQL 持久命令再投递 Redis；V2 以 WorkflowRun/Step 和冻结 Evidence 接续执行；
- 同一 `clientRequestId` 返回同一命令，不重复创建任务；
- V1 兼容入口可用 `@设定`、`@剧情`、`@写作`、`@校验`、`@编辑` 指定默认主责方向；
- V1 无法稳定识别时回退问答；V2 自然入口必须澄清或明确失败，不默认为问答；
- 正文和大纲支持来源绑定的选区改写，请求不把 `selectedText` 当作权威来源。

当前限制：

- 同一 `novelId` 同时只执行一个独立队列任务；不同小说最多并行 3 个任务；
- 所有普通 Agent、Reviewer、质量检查、中短篇和文风画像共享最多 3 个模型调用槽；
- 生产默认一个 Agent worker，`AGENT_MAX_CONCURRENCY` 只允许 1～3；
- 默认目标正文长度为 4,000 字，公共请求硬范围为 1～10,000,000；它只是目标，模型输出能力、计费额度和内容结构仍会限制实际结果；
- 当前不把供应商 `length` 结束原因当作自动续写信号；被截断响应直接失败；
- 没有多章无人值守连续生产、自动发布或“整本书一次生成”；
- Agent 聊天正文按普通文本渲染，不解析 Markdown；
- Agent 不连接 PostgreSQL，只能通过 Core 内部工具网关读取和提交业务事实。

### 8.9 ReviewArtifact、复审和正式应用

当前功能：

- Agent 对正文、设定、大纲、伏笔、Beat Plan 和视频镜头方案的正式变更先创建 ReviewArtifact；
- 草案保存 revision、evaluation、Diff、来源任务、来源版本和状态；
- Reviewer 可并行复审，合并为通过、返工、确定性 patch 或阻断；
- 完整返工生成新 revision，严格 patch 只修改可定位目标；
- 作者可以批准、带编辑批准、要求修改或丢弃；
- 结构化 `agent_updates` 支持只应用用户明确选择的 section 或 item；
- 选区草案只接受 replacement，Core 应用时再次校验来源版本、范围和哈希；
- 正式应用、草案状态和恢复命令在同一 Core 事务中处理；
- Redis 事件失败不能否定已经提交的 PostgreSQL 业务结果。

当前限制：

- Agent 草案不能自动成为正式内容；
- `revision_brief` 永远不能正式应用；
- patch 目标缺失、多重命中、重叠或版本冲突时不会静默升级为全文重写；
- 旧 `video_scene_plan` 只保留历史兼容，不得成为新的产品入口；
- SSE 事件只承担展示，审核成功与否以 Core 权威状态回读为准。

### 8.10 积分与模型计费

当前功能：

- 注册赠送 1,000 积分；
- 展示当前余额和近期积分流水；
- 模型调用前预授权余额，余额不足时不开始调用；
- 调用后按真实 prompt、cached 和 completion token 上报并扣费；
- 重复 usage 回调不重复扣费；
- 可按写作任务查询调用次数和 token 汇总；
- 可记录缓存未命中和 reasoning token 诊断字段；
- 失败场景可按明确规则写退款流水。

当前代码计价为：

- 非缓存输入：每 token 0.001 积分；
- 缓存输入：每 token 0.00002 积分；
- 输出：每 token 0.002 积分；
- 单次调用最小输出预算：128 token。

当前限制：

- 没有在线支付、微信/支付宝、银行卡、订阅套餐或自动续费；
- 充值页只提示联系管理员人工充值；
- 没有充值订单、发票、优惠券、套餐管理和面向用户的退款申请；
- 没有管理员充值后台；
- 视频真实供应商调用尚未获生产开放授权，不能把开发任务视为正式商业计费能力。

## 9. 长篇剧集制作详细功能

### 9.1 当前可用状态

Episode 视频 P0～P4 的仓内实现与本地隔离验收已经完成：新生产链、剧本与分镜候选、稳定镜头、影响复核、视觉定妆、关键帧、
制作基线、逐镜 simulated MP4、Take、粗剪、声音字幕和整集导出已经接通。Web、公共 API 和普通 CLI 只提供
这条新链；旧 chapter-adaptation、旧 render/take/post 的公共与内部路由、旧 UI、旧 CLI 和后台装配均已退出。

当前仍属于“仅开发环境”能力：

- `VIDEO_PREVIEW_ENABLED` 默认关闭，production 环境主动拒绝视频写入、调度和真实 Seedance；
- 模拟模式只验证业务、媒体归档和恢复链，不证明供应商画质、音色、用量或计费；
- P4 retirement 脚本只在隔离 PostgreSQL 通过正向、幂等、旧行 guard 和整事务回滚验证，没有应用服务器；
- 当前 schema-contract、生成 jOOQ 与未装配旧仓储源码仍保留旧投影，实际服务器晋升时必须在另一次授权和备份下同步处理。

### 9.2 视频项目、素材与视觉定妆

当前功能：

- 为长篇小说创建视频项目；新 Episode 主链使用 series、项目画幅和语言等稳定上下文；
- 画幅支持 16:9、4:3、1:1、3:4、9:16、21:9 和 adaptive；
- 上传 JPEG、PNG、WebP、MP4/MOV、WAV 和 MP3，并按魔数与 ffprobe 核对真实格式、时长和媒体事实；
- 图片最大 30 MiB、视频最大 200 MiB、音频最大 100 MiB；文件只通过受控 storage key 访问；
- 素材必须由作者声明权利，只有 `confirmed` 且锁定的同项目素材才能进入正式视觉、制作输入、音轨或供应商请求；
- 角色、地点和物品支持文字设定／视觉定妆、候选、不可变版本、历史读取、变体和 revision CAS；
- 每镜最多冻结 20 份有序参考，记录素材身份、版本、哈希和强度；后来换图不会改写旧制作依据。

系统不生成角色图、场景图或道具图，也不代替作者确认权利。当前没有人脸训练、LoRA、跨项目素材市场、
自动版权识别或素材文件删除能力。

### 9.3 Episode、来源与单集剧本

当前功能：

- Episode 是项目下的稳定身份；改名、调序和更换来源不改变 episodeId，集号只承担展示顺序；
- 一集可选择一个或多个章节范围，一章也可被多个 Episode 使用；Core 分别冻结章节身份、原文、Unicode 范围和哈希；
- 剧本工作稿保存概要、稳定 sceneId／lineId、动作、对白、旁白、来源绑定与承接依据，使用 revision CAS 自动保存；
- AI 起草和修订使用独立 V2 Run，只生成可恢复候选；采用候选只更新工作稿，正式确认是另一项作者操作；
- 正式剧本版本、来源集合和跨集依赖不可变；后续集必须引用前集的确切正式版本、节点、状态 key 与叙事时间；
- 小说原文更新只提示新来源，作者选择同步后产生新的来源集合和工作稿，不重写旧快照。

### 9.4 分镜、影响复核与制作基线

当前功能：

- 分镜从确切正式剧本派生；稳定 shotId 与不可变 ShotVersion 分离，复制、替换、拆分和合并保留类型化 lineage；
- 分镜工作稿使用 revision CAS，作者另行确认正式版本；确认新版分镜不会自动替换现有制作基线；
- AI 可起草整份分镜，也可只修订作者选择的稳定 shotId；Core 合并保留范围外镜头，不相信模型的全量覆盖声明；
- 影响复核区分直接差异、可能连带影响和作者明确沿用，旧决定在依据变化后不能继续应用；
- ProductionBaseline 冻结剧本、分镜、全部镜头顺序、提示词、参考、画幅、时长、模型、执行模式和费用确认；
- 初始基线允许镜头处于 `pending` 且没有 Take；生成成功只产生不可变 Take 候选，作者采用后通过 TakeAdoption 和新基线表达使用关系；
- 剧本、分镜、制作和交付 head 相互独立，批准上游新版不会清空旧制作或旧成片。

### 9.5 提示词与关键帧

当前功能：

- 每镜保存结构化制作意图、声音要求、摄影、动作、负面约束和最长 2,500 字的 Seedance 提示词；
- 分镜工作稿用 revision CAS 保护提示词修改；确认制作基线时为每镜创建不可变 PromptVersion，并冻结视觉参考与内容哈希；
- 每镜可从本项目权利已确认且锁定的图片中选择首态 `initial_state`、过渡锚点 `transition_anchor`、末态 `end_state`，每种角色最多一张；
- 关键帧版本随 ProductionBaseline 在同一事务创建并绑定确切 shotVersion，不另设会静默漂移的 current head；
- 连续性检查可以提示前镜末态和后镜首态的问题，但软质量建议不替代作者确认；
- 当前制作基线使用 `video-production-shot-input/1.2`，视觉参考与关键帧合计最多 20 张，并冻结素材权利状态与 UTC 锁定时间；之后修改提示词、定妆或图片不会改写旧任务。`1.0`／`1.1` 只用于历史模拟读取，真实生成必须新建 `1.2` 基线。

当前新 Episode 公共链没有 Take 抽帧或图片生成入口，也未把关键帧承诺为供应商精确首尾帧复现。

### 9.6 逐镜生成、媒体归档与选片

当前功能：

- 任务只能从同集 ProductionBaselineShot 的 `inputSnapshotJson` 构造，不使用旧 adaptationId 或 shotPlanVersionId；
- 当前供应商方向固定为 Seedance 2.5，模型默认 `doubao-seedance-2-5-260628`；真实 submit/query 只进入已有隔离函数；
- 默认 `SEEDANCE_EXECUTION_MODE=simulated`，无需密钥并生成带 `simulated_placeholder` 标记的可播放 MP4，不记录供应商用量；
- 任务冻结 reference 模式、4～12 秒、720p、1～20 份参考、声音、水印和输出格式等完整输入；
- `submission_unknown` 禁止普通 retry 和同镜新任务绕过，必须核对原提交；明确失败才可受控重试并复用原冻结清单；
- 供应商临时 URL 不作为产品事实；Core 归档、ffprobe 验证媒体后只创建一个不可变 Take，并保存可得的 lastFrame 和完整 usage 事实；
- 归档失败恢复原任务，不创建替代任务；作者通过有界 Take 列表比较并用 CAS 记录采用，原 Take 与生成清单不变。

当前没有公共取消供应商任务、一键整集付费生成或真实供应商端到端验收。

### 9.7 粗剪、声音字幕与整集输出

当前功能：

- 粗剪、混音和导出全部以 episodeId 与确切 ProductionBaseline 为根，历史版本只读，head 使用 revision CAS；

- 附加 WAV／MP3 必须同项目、权利已确认并锁定；字幕绑定正式 shotVersionId 和 scriptLineId；
- 声音版本绑定确切粗剪版本；粗剪改变只会把旧声音标为过期，不会静默套用；

## 12. 内部支撑与运维能力

### 12.1 Core 与 Agent 边界

- 浏览器只访问 `/api/v1/**`；
- 24 个 Core 内部操作覆盖质量、RAG、文风、模型授权与计费、Agent 工具网关、V1 写作兼容、V2 Step、草案复审和 Episode 剧本／分镜回调；
- 内部请求同时校验直连网段、Ed25519 服务身份、请求体绑定、短有效期和重放保护；
- Agent Service 不接收 `DATABASE_URL`，不加入数据网络，不直接写小说数据；
- Nginx 对公网阻断 `/internal/**`。

### 12.2 耐久任务和恢复

- 写作命令、质量运行、文风画像、RAG 索引、Episode 剧本／分镜 Run、渲染和导出都以 PostgreSQL 为长期事实；
- Redis 承载队列、短期事件、租约、限流和重放保护，不是最终业务状态；
- 后台 dispatcher/reconciler 按到期行补投或对账，Core/Agent 重启后可继续；
- 完成、失败或取消的 Agent 队列 tombstone 默认在 Redis 保留 7 天，至少 1 天；
- Redis 内存上限为 64 MiB，策略为 `noeviction`；满时明确拒绝新写入，不能淘汰业务队列或防重放键；
- 后台任务失败会退避重启，并反映在 readiness，而不是伪装健康。

### 12.3 日志与调试

- 人工工作流日志记录完整模型输入输出和规范化元数据，不记录服务令牌、计费 grant 或 DeepSeek
  `reasoning_content`；
- 大日志按帧保存，不静默截断；残缺尾部需隔离后恢复；
- 工作流调试读取默认关闭；开启后仍校验登录、作品归属和服务权限；
- LangGraph Studio 只用于开发调试，不是作者正式工作区。

### 12.4 部署与数据

- 生产由宿主机 Nginx、Compose Nginx、Web、Core、Agent 和 Redis 组成；PostgreSQL 14 运行在宿主机；
- 只有 Nginx 对外发布端口，Agent 不发布宿主机端口；
- 2 核 2 GB 是当前默认部署预算，每个 Python 服务一个 worker；
- 发布在 Runner 预构建镜像，服务器不现场构建；
- 发布失败时按经验证的上一组不可变镜像恢复 Web、Core 和 Agent，回滚成功仍表示本次发布失败；当前正式库
  已有 V2 Run，只允许 V2-aware 兼容组合，禁止 DDL rollback 和 V1-only Python Core 镜像回滚；
- 应用启动不自动建表、删表或迁移；schema guard 只读核对结构；
- 只有用户明确批准的具名迁移可以在备份、隔离验证和门禁下执行。

## 13. 横向产品不变量

这些规则不是实现细节，Java Core 重写后也必须保持：

1. **作者拥有最终正式写入权。** Agent 对正文、设定、大纲、伏笔、Beat Plan 和视频方案的正式变更
   必须经过持久草案和作者确认。
2. **不同数据层不能混写。** 正文、章节进展、故事进展、设定、大纲、伏笔、Beat Plan、视频方案和
   后期决定各自独立。
3. **来源必须可重建。** 选区、Episode 来源集合、剧本、分镜、制作基线、渲染和导出都冻结来源版本、哈希或不可变清单。
4. **不静默截断。** 正文、草案、Diff、模型输出、工具结果、日志和持久数据不能为了通过限制而截断；
   超限必须失败、分段或要求用户处理。
5. **写操作必须防重复。** 能提供 `clientRequestId` 的入口按稳定指纹幂等；不能提供的入口在网络结果
   不确定时先回读核对，不能盲目重试。
6. **并发冲突必须显式。** 正文、资料、草案、镜头方案、视觉参考、提示词、Take 和后期 head 使用
   时间戳或 revision CAS，旧页面不能覆盖新版本。
7. **异步受理不等于完成。** 前端和 CLI 必须回读任务、草案或 outcome；SSE/JSONL 只辅助观察。
8. **历史版本不可变。** 恢复或修改创建新版本，不能重写旧版本事实。
9. **软质量建议不替代作者。** 节奏、景别、空镜、平均时长和视觉风格等建议不能无证据地变成硬阻断。
10. **服务边界不可绕过。** Agent 无数据库权限，浏览器和 CLI 无内部接口权限，正式媒体必须经过素材
    权利和受控存储。

  浏览器验证码核验、首次自动建号和再次登录复用仍待用户验收；无邮箱体系；
- 无账号找回、改密、注销、风控后台和客服工单；
- 无在线支付、订单、订阅、套餐、优惠、发票和用户退款申请；
- 无管理员运营后台；
- 无内容商业化、版权交易或收益分成。

### 14.2 协作与内容管理

- 单用户所有权，没有团队、分享、评论、审稿角色或多人实时编辑；
- 无小说删除、归档、复制、导入、整书导出和发布；
- 无章节删除、重排、批量操作和跨书移动；
- 无富文本、批注、修订模式和离线编辑；
- 无移动端专用体验。

### 14.3 AI 写作

- 不能无人值守连续生产整本书；
- 章后质量检查只有一致性；
- RAG 只覆盖参考资料，且依赖可选 Embedding 配置；
- 文风只从 TXT 生成；
- 模型被截断时不自动续写；
- 当前模型供应商和额度会直接影响可用性、时延和成本。

### 14.4 视频

- P0～P4 的仓内实现与本地隔离验收已完成，但生产功能、真实 Seedance 和供应商调度继续关闭；
- P4 已完成旧入口与运行装配退场，retirement SQL 只在隔离 PostgreSQL 验证，未应用服务器；
- 当前只接 Seedance；模拟 MP4 明确标记为 `simulated_placeholder` 且不产生供应商用量；
- 无图片生成、TTS、声音克隆和音乐生成；
- 无公共取消供应商渲染和一键整集付费生成；多章取材与一章多集已经支持；
- 粗剪只提供基础片段、明确省略／重复、原声保留／静音和基础转场；
- 无高级 Retake、视频内生成式编辑、调色、复杂特效和发布分发；
- A／B／C 本地 simulated 组合 E2E 与完整 `./mvnw verify` 已通过；真实付费调用尚未作为生产能力验收。

### 14.5 自动化与平台

- CLI 不是公共 API 全量镜像；
- macOS Operator Skill 的 Java 实际入口已切换并完成离线验收，生产登录与 `auth.whoami` 已通过；
  Python CLI 保留为契约对照，生产隔离 canary 与全量门禁已通过，Windows 实机仍未验收；
- 生产是单机 2 核 2 GB 预算，不是多地域、高可用或水平扩展架构；
- PostgreSQL schema 默认冻结，应用不能自动迁移；
- 当前没有公开 Webhook、第三方插件市场或外部开发者 API 产品。

## 15. Java Core 重写的产品验收基线

Java 重写的第一目标是行为等价，不是顺便增加功能。完成迁移至少要证明：

- 两种创作模式、当前 141 个公共路径／182 个操作和 Agent 所需 24 个 Core 内部操作保持契约语义；
- 当前 152 个普通 CLI 命令在 Python／Java 实现及跨语言 parity 中保持；Operator 的受限白名单另行管理；
- 登录 Cookie、资源归属、积分预授权与扣费结果一致；
- 章节自动保存、状态门禁、质量失效规则和完整字数统计一致；
- CreativeOperation、ReviewArtifact、部分应用、选区来源绑定、SSE 恢复和任务对账一致；
- 视频在生产继续关闭，不能因迁移意外启用；开发环境的 Episode、剧本、分镜、制作基线、关键帧、Take 和后期版本语义一致；
- schema 指纹守卫、无自动 DDL、受控文件存储和服务身份边界一致；
- Java 单切时要求对当前功能和限制的 TDD/差异测试全部通过；现正式库已有 V2 事实，Python Core 镜像仅历史
  留存，不再具有现正式库回滚资格。

手机号登录已在 Core 完整切换后通过 `docs/specs/2026-08-27-aliyun-phone-auth.md` 独立实施，仍受迁移和
生产开关门禁；在线支付和其他商业功能继续要求另立规格。
